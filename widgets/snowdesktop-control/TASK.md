# Task guidance

1. **Understand the requested result.** The user may want an explanation, the current setting, a configuration change, an app surface opened, or a screenshot, recording or demo. Inspect the state that bears on the request. When the user names another product or operating system, identify the effect they want to reproduce.
2. **Resolve open decisions one at a time.** Assume the user is new to SnowDesktop. Explain what you found in everyday terms. For an open-ended first-time or whole-desktop setup, start from the priorities the user has already shared. Ask about everyday use when it is unclear. Wait for each answer and use later turns for remaining choices that materially change what is visible, how it is reached, or how much space it takes. Continue when the user has answered or delegated those choices. Explain options through what the user would see or do. Make routine, reversible details part of the proposal.
3. **Work within the request.** Use the current state or product documentation to answer questions. For requested changes, discover the controls supported by the running version and explain consequential effects before applying them. For organizing the desktop, moving components or rearranging a layout, use the [desktop layout guidance](tasks/desktop-layout.md).
4. **Verify the requested result.** For configuration, read back the changed settings and inspect the intended composition. Verify opening, searching, or other feature behavior when the user asks to use or troubleshoot it. For screenshots, recordings and demos, confirm that the requested files were produced. For informational requests, answer with the relevant findings.
