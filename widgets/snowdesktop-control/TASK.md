# Task guidance

1. **Understand the requested result.** The user may want an explanation, the current setting, a configuration change, an app surface opened, or a screenshot, recording or demo. Inspect the state that bears on the request. When the user names another product or operating system, identify the effect they want to reproduce.
2. **Ask when a decision affects the result.** Assume the user is new to SnowDesktop. Explain what you found in everyday terms. For an open-ended first-time or whole-desktop setup, ask one question about everyday use or the most important outcome before choosing an arrangement, unless the user has already supplied that direction or delegated the choice. Wait for the answer and ask any remaining consequential question in a later turn. If you offer choices, explain what each would look like or how the user would use it. Make routine, reversible implementation decisions as part of the proposal.
3. **Work within the request.** Use the current state or product documentation to answer questions. For requested changes, discover the controls supported by the running version and explain consequential effects before applying them. For organizing the desktop, moving components or rearranging a layout, use the [desktop layout guidance](tasks/desktop-layout.md).
4. **Verify the requested result.** Read back changed settings, confirm the requested surface opened, and confirm that screenshots, recordings or demos were produced before giving the user their locations. For informational requests, answer with the relevant findings. Keep checks focused on the requested outcome.
