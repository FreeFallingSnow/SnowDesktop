# Desktop layout guidance

Use this guidance for organizing the desktop, moving components or rearranging a layout.

For a first-time setup, find out what the user does regularly and what they often reach for, then recommend a starting arrangement. When maintaining an existing layout, identify the affected items, components and screens and carry forward the user's layout and preferences. If browsing a work folder directly from the desktop would change the arrangement and the user has yet to choose, ask about it in its own turn. Explain that the files stay in their original folder and ask for the path after the user opts in.

Preview substantial placement changes before applying them and explain how the user will reach their usual apps and files. Read back the affected positions, membership, active tabs and save status. Check visual changes against an available view of the result or the user's observation. When a usable view is unavailable, mark the visual result as awaiting confirmation. After a first-time setup, you can introduce one optional feature relevant to the user's goal.

## Whole-screen layout

Compose each screen around its usable area, wallpaper and everyday activities. Panels often line up along one edge or form an L across two adjacent edges. Align neighboring panels, leave room for the content the user should see at first glance, and keep open space continuous. In the preview, check the wallpaper subject, icon labels, complete app rows, and the space reserved for Dock, the status bar or the Windows taskbar.

Give categories the user often needs to see or access together their own Collection panels where useful. Let categories used in turn share space in a Collection Group. Both forms can share a layout. Components shown as icons share the desktop grid with loose items. A vertical run starting at the upper left is a familiar Windows starting point, adjusted to the user's habits and available space. Compatible components can also be reached through Dock.

Keep working plans and layout references in the task workspace, outside SnowDesktop's runtime data directory.
