# Desktop layout guidance

Use this guidance for organizing the desktop, moving components or rearranging a layout.

For a first-time setup, [learn which activities matter most](../TASK.md). On a mixed desktop, settle visibility and access for each important kind of content. A priority choice sets the relative emphasis. When other content still has an open decision, ask about it in a later turn. For files, the useful distinction may be seeing working files at a glance or opening an entry to browse them. Ask about browsing a working folder directly from the desktop in its own turn when it would change the plan. Explain that the files stay in their original folder and ask for the path after the user opts in. For a scoped edit to an existing desktop, carry forward the user's layout and preferences.

Preview substantial placement changes at the scale of the whole screen before applying them. Show or explain which items will be immediately visible, how the rest will be reached, and what the panels and loose entries will occupy together. Read back positions, sizes, presentation, membership and save status. Check the composition at normal desktop scale against a usable view or the user's observation. Mark the visual result as awaiting confirmation when that evidence is unavailable. After a first-time setup, you can introduce one optional feature relevant to the user's goal.

## Whole-screen layout

Start with the wallpaper and usable grid on each screen being rearranged. Use a desktop view or wallpaper reference to identify the focal area, where labels will read clearly, and which area should stay open. An obscured view gives only partial evidence. If you cannot see enough of the wallpaper to guide placement, ask which area the user wants to keep visible and treat the visual fit as provisional.

Choose one edge for the panels or two adjacent edges for an L-shaped arrangement. Use the edge as an anchor for the composition. Related panels can share an outer edge, sit side by side, or step inwards where their sizes differ. Use the native grid for placement and align the edges that clarify relationships between panels.

Give each panel room for the content the user needs at a glance and the controls they use. Check actual visible rows, labels and tabs, then judge the occupied area and open space together at screen scale. Use the edge length that the content and controls justify. Vary widths and heights where that improves access or visual balance. Keep room for the wallpaper and any space reserved for system or SnowDesktop bars.

Give categories the user often needs to see or access together their own Collection panels where useful. Let categories used in turn share space in a Collection Group. Both forms can share a layout. Components shown as icons share the desktop grid with loose items. Lay out the items that remain loose as part of the same composition. A compact vertical run starting at the upper left is a familiar Windows starting point, adjusted to the user's habits and available space. Check the final positions in the preview, close accidental holes within each run, and keep deliberate spacing between groups that need visual separation. Compatible components can also be reached through Dock.

Keep working plans and layout references in the task workspace, outside SnowDesktop's runtime data directory.

Design references include [Fluent 2 layout](https://fluent2.microsoft.design/layout) for grouping, spacing and alignment, and [Apple HIG layout](https://developer.apple.com/design/human-interface-guidelines/layout) for visual hierarchy and grouping.
