## 本轮候选

把状态栏发起的系统快捷键交给独立 GUI 线程及无父窗口、无 owner 的临时窗口。
必须确认该窗口实际拥有 foreground、active 和 focus，才发送一次快捷键；
不会调用 `AttachThreadInput`，不会在激活失败后退回桌面 UI 线程发送。
这是对已观察到的共享桌面输入队列路径的隔离尝试，不是已证明有效的根因修复。

接入范围为任务视图、通知、系统日历、快捷设置及显示桌面：
Win+Tab、Win+N、Win+A、Win+D、Win+Alt+D，保留现有系统版本映射。
自绘搜索、本地控制面板和直接使用输入法 API 的入口不伪装为系统快捷键。

所有系统快捷键等待实体鼠标按钮、修饰键及目标键释放，取得焦点后再次检查。
UI 通过原调度器异步轮询，不同步等待工作线程。取消只能在注入提交前生效；
输入接受后，临时窗口保留消息循环，直到前台交接或 1500 ms 期限结束。
任务视图现有的过渡保护继续保留；不重试快捷键、不重放被取消的操作。
部分接受时仅尽力释放本次未匹配的合成按键，不释放用户实体修饰键。

`Sent` / `input-accepted` 只表示 `SendInput` 接受数量符合预期，
不表示输入已全部交付、系统面板已打开或故障已经消除。
Windows 可能拒绝前台交接；该候选会取消或报告失败，需要实际验证入口可用性。

用户在 17:47–17:49 高频点击任务视图及通知后，遇到提示音但面板不展开，
点击桌面空白再点击能够恢复。运行 EXE 的 SHA-256 为
`00391704BCD6E381F5C68DDBC312D94AA6B18BE70F99F3A9212F668937F88715`，
对应候选 `57ff862859f65b5ca2a588d006cf7964dae15974`；宿主 PID 47548、UI TID 48512。
原始记录保存在上述证据目录的 `candidate-click-failure-1749/activation-and-input.log`，
分项复核见同目录 `findings.md`。

已确认一条候选自身的错误路径：Notifications generation 128–131 的初始
foreground 为 NULL，约 17 ms 后直接 failed，既没有 relay-start，也没有
send-input-begin。`StatusBarShellShortcutRelay::Start` 对空前台直接返回空对象，
调用方按失败处理并发出提示音，没有发送快捷键。
`GetForegroundWindow` 在窗口失活期间允许返回 NULL；该状态本身不表示不能
尝试取得前台，不能用作无条件拒绝的依据。

同一时段 generation 126/127 有 relay-start，随后在注入前失败，初始前台非空。
现有日志没有区分激活、前台归属、focus 检查等分支，尚不能将这些失败也归为 NULL。
实体按钮消息及时交付并由应用主动拒绝，与原现场内核队列长期延期的证据不同；
提示音不是已经确认的原故障前兆，原故障是否仍会出现也尚未验证。

该候选的实机入口可用性验证失败。原有标准构建及两项定向测试的通过结果仍有效，
但没有覆盖空前台输入，不能替代本次用户观察。后续修正需允许 NULL 作为精确起点，
继续在其他窗口取得前台时取消，并分别记录注入前失败原因。
