# 状态栏收敛与原生界面实施计划

更新：2026-09-26。本文是当前实施顺序和范围的真源；[STATUS_BAR.md](STATUS_BAR.md) 保存逐项反馈和历史验证证据。后续用户指令优先，冲突项在这里更新，不继续沿用旧界面方案。

## 1. 已确认的产品边界

| 项目 | 最终要求 |
| --- | --- |
| 技术范围 | 除设置外，状态栏、控制中心、托盘、日历、资源面板及提示改为原生自绘。已有原生 Dock、菜单、搜索、Lua 面板继续复用；不再制作一轮 WinUI 弹窗布局。 |
| 栏体 | 只支持顶部、底部；AppBar 占位，普通状态置顶且不抢焦点；按屏全屏隐藏所有附属窗口，保留占位。只绘制面向桌面的一条边。 |
| 排列 | 左侧系统菜单、搜索及可选资源信息；独立栏的日期时间居中；右侧固定托盘、折叠菜单、网络／音量／电量合一控制区、最右通知按钮。资源信息默认关闭且固定宽度。 |
| Dock 合并 | Dock 靠边且与状态栏同侧时自动合并，不提供开关。Dock 内容居中，侧区避让，仅注册一次占位，维持现有时钟避让规则。 |
| 两种菜单 | 栏体右键只有“状态栏设置”“任务管理器”。左侧系统菜单提供任务管理器、终端、系统设置和电源动作；睡眠、重启、关机二次确认。**不增加右键主题入口或主题选择。** |
| 控制中心 | 网络／音量／电量同组打开唯一面板；Ctrl 点击打开系统控制中心。简洁、合理即可，不追求逐像素复制 Windows。声音按钮按状态分档，滚轮只在音量区域生效。 |
| 媒体 | 控制中心下方独立窄卡片，单行依次为封面、标题、上一首、播放暂停、下一首；无媒体不占位，不设媒体详情菜单。当前草稿高 56 DIP，最终以真实文字／命中范围检查调整，不新增高度设置。 |
| 设备子页 | 按设备选择、状态、主要动作组织；长列表滚动条靠外缘；子页切换立即重排和定位。Wi-Fi 不单列已保存网络；蓝牙关闭不等于硬件不可用。 |
| 日历 | 左侧显示选中日期及设置中的第二历法；今天按钮在顶栏；右侧完整月历，下方只读日程和“管理日程”设置链接。不再做一套日程编辑器。 |
| 资源面板 | 点击 CPU／内存／GPU／网速后显示简洁曲线和指标；未知不显示成 0。GPU 按有效身份去重，不合并真正存在的同型号显卡。 |
| 托盘 | 采集完整性和原应用激活为最高业务优先级。原应用右键菜单显示时保留托盘展开面板；直接拖拽排序、固定、取消固定；紧凑网格，无多余标题或原生托盘按钮。 |
| 提示 | 自绘。稳定目标的提示随数据原位更新，特别是滚轮调音量后的数值；不反复关闭重开、不重置悬停计时。 |
| 主题入口 | **主题与材质页只保留状态栏设置超链接；主题编辑和场景覆盖在状态栏设置页，与任务栏一致。** 栏体默认跟随全局，支持完整全局预设和自定义；自有弹窗沿用弹窗主题。 |
| 场景覆盖 | 复用任务栏已有场景语义和监视状态，按屏处理；系统界面打开、存在最大化应用、存在普通应用，优先级与任务栏保持一致。每条可启用并选择跟随全局／预设／自定义；未命中恢复状态栏默认主题。 |
| Lua | 复用内部绘制、输入和系统服务；不因为本次迁移另造一套公开控件语言。原计划尚缺的系统控制写接口单独补齐，编辑前公告具体 API。 |
| 范围排除 | 左右栏、自有通知历史、状态栏任意 Lua 布局、媒体详情页、重复的控制中心选项、右键选主题均不实施。 |

## 2. 代码审查得到的复用边界

| 层 | 现有资产 | 本轮责任与限制 |
| --- | --- | --- |
| 图形与材质 | 应用 D2D／DirectWrite／DirectComposition、`DrawWidgetPanelBackground`、`DesktopBackdropCompositor` | 复用图形设备、主题背景与缓存。独立弹窗增加宿主和裁剪，不自行创建另一组常驻设备或采样线程。 |
| 控件描述与布局 | `widget_view_tree` 已含按钮、滑条、列表、滚动、图表、月历；`widget_engine.cpp` 的绘制目前还耦合 `D2DState` | 先提取本轮需要的内部绘制／测量辅助或适配已有节点，范围限于当前面板；不重构整个 Lua 引擎，也不长期维护两套同类控件算法。 |
| 输入与无障碍 | `WidgetInteractionRegions`、`widget_view_accessibility`、`WidgetAccessibilityProviderHost` | 复用稳定 key、裁剪命中、数值动作、焦点和 UIA 语义。独立 HWND 只适配消息、捕获与托盘拖拽，不再自创一套键盘和滑条协议。 |
| 提示 | Lua 已有自绘提示的测量／排布代码；状态栏现用 `TOOLTIPS_CLASSW` | 提取共用提示内容与测量，增加不激活的独立宿主以免 32 DIP 栏体裁掉提示。主题、屏幕避让、数据更新复用同一路径。 |
| 弹窗生命周期 | `UiAnimationScheduler`、现有边缘动画、原生菜单和搜索关闭流程 | 单一协调入口负责互斥、关闭后打开、焦点、全屏和销毁；业务页不能各自创建窗口／恢复焦点。 |
| 数据与控制 | `WidgetSystemDataProvider`、`system_control::Service`、`ControlFeedback` | 原生界面与 Lua 共享订阅和异步任务。UI 只读快照，设备扫描／控制不进入绘制线程；按设备保留最后一次请求的反馈。 |
| 托盘 | Hook 有界采集、`tray::Service`、`tray_model`、`tray_order`、`tray_focus` | 协议、身份、恢复、激活与窗口几何继续独立；界面只消费图标快照和提交手势，不在控件里解析 Explorer 私有协议。 |
| 配置 | `StatusBarSettings`、设置 Controller／IPC、任务栏场景判断、主题编辑器 | 设置只存配置；运行时场景外观按屏计算，不把临时主题反写用户默认值。入口、IPC、保存、恢复、全部语言一起改。 |

### 统一生命周期约定

- 一个状态栏弹窗宿主承载四种业务页。控制中心与媒体条是同一宿主中的两张卡片，中间透明且不接收输入；Tooltip 是独立、不激活的提示宿主。
- 状态只有关闭、打开中、已打开、关闭中；切换保留最新目标，先完成旧面板关闭再打开新面板。相同按钮切换关闭，栏体空白、Esc、离开本应用、全屏和停用可取消待打开请求。
- 菜单和搜索接入同一切换协调点，仍使用现有原生宿主。第三方托盘菜单的保留例外仅限本次激活目标，不允许永久阻止外部点击关闭。
- 输入、布局、绘制使用同一份已提交的矩形与稳定身份。数据更新不能把按下目标替换成另一个图标，不能在回调执行中销毁正在访问的模型。
- 内容、主题、布局、提示分别失效；数值改变只更新相关内容，提示原位更新。缓存文字格式、位图和背景，未变化不反复重建整棵内容／提交整面板。
- 关闭释放订阅、捕获、定时器、UIA 连接、图标几何和玻璃对象；迟到任务按代次丢弃。关闭后没有页面刷新轮询。休眠、DPI、显示器和图形设备变化沿用宿主恢复路径。
- 开关、滑条、列表、提示必须从一开始包括键盘、屏幕阅读器、浅深色和高对比边界，不能完成自绘后再补一套交互模型。

## 3. 实施顺序与交付批次

顺序用于减少依赖返工，不代表每一步都编译或发一个测试版本。

| 顺序 | 工作单元 | 完成边界 |
| --- | --- | --- |
| 1 | 收敛共享基础与现有自绘草稿 | 选定现有控件／输入／UIA 的最小复用方式；完成弹窗协调、材质和裁剪、提示更新、所有权及缓存。到此不做像素级微调。 |
| 2 | 托盘业务链 | 对照固定 YASB 版本核查初始化与现有图标补采、增删改／版本／隐藏状态、重连代次、完整鼠标和键盘回调；原生捕获与拖拽消费同一快照。先证明采集和激活链，不能只画夹具图标。 |
| 3 | 四类面板统一迁移 | 控制中心与窄媒体条、紧凑托盘、日历日程、资源曲线一次性接入共享原生宿主；迁移时保留既有有效行为，不继续修改将删除的 WinUI 页面。完成滚动、边界、切页尺寸与统一动画。 |
| 4 | 设置与场景主题 | 迁移主题编辑位置、保留主题页链接、接入每屏场景外观；同步 Controller／IPC／保存／恢复／旧路由和本地化。右键仍只有两项。 |
| 5 | 第一集中候选验收 | 以上形成可用的一批后统一标准构建，保存 `try`，用实际生产渲染离线看图和最小充分逻辑回归；稳定输入再做一次有效全量。一次提交完整手测清单给用户。 |
| 6 | 原计划的 Lua 控制补齐 | 复用已稳定后端和控件；补充缺失写任务、独立权限、手势／确认、取消、超时与预览无副作用；公告 feature、旧宿主降级和文档／类型更新。单独形成可验证批次，不借此重写面板。 |
| 7 | 资源采集与实机收尾 | 系统监控的适配器选项、失效数据与订阅回归、同输入的资源对比；AMD 原始样本／同时段对照、实际第三方菜单和桌面多屏验收继续独立跟踪。 |

第 2 项中与宿主无关的协议修正不需要等待全部控件布局；但不另起一轮 WinUI 修修补补。没有证据的兼容猜测不混进已验证结论。

### 托盘专项，不与面板美化混为一个问题

| 用户反馈 | 分层检查及收敛标准 |
| --- | --- |
| 图标不全 | 依次核对捕获、解码、模型身份／版本、隐藏过滤、固定／折叠分流及绘制；记录缺失所在层，不能把所有缺失都归为 WinUI。 |
| 微信右键、PowerToys 单击无效 | 先核对真实释放事件是否到达服务，再核对图标版本、消息序列、坐标、权限及返回焦点。自有 Hook 协议夹具只能证明回调链，不替代这两个应用的验证。 |
| WPS／抖音向上越屏 | 先更新真实图标屏幕矩形和点击坐标。若目标应用自行错误定位，兼容约束限定为本次点击的进程、附近新弹出的菜单、短时间和有限纠正次数；禁止遍历移动普通应用窗口。实际效果待对应应用验证。 |
| 排序、固定拖动无效 | 原生按下／捕获／阈值／释放状态一次打通；拖到栏上固定、拖回展开区取消固定、区内改顺序，提交一次持久化事务，取消不改设置；同时给出拖动反馈。 |
| 菜单展开保持 | 原应用菜单的生命周期与自有面板互斥规则分开；焦点票据、外部点击、全屏和宿主退出都要能终止保留状态。 |

## 4. 当前实现状态与验收边界

这部分是工作区事实，不是验收结果：

- 候选 54 的标准构建、86 张浅深色生产图片、完整回归 120/120、自有图标真实托盘采集 1/1 均通过，无编译／链接警告。52／53 及 54 中间失败完整保留于实施记录，不重写为成功；桌面和第三方应用仍待验。
- 新增 `native_ui_scene`、`system_panel_model`、原生 `system_panel`，应用与 CMake 已切换；`system_panel_preview.cpp` 已迁移旧 30 个面板预设至生产原生模型和绘制。当前只有设置子进程初始化 WinUI，未编译旧 WinUI 弹窗源码。
- 输入复用现有 `WidgetInteractionRegions`，滑条几何与 Tooltip 文字测量也接回 Lua 控件；原生宿主接现有 UIA provider、键盘滚动和焦点事件。定时刷新只在内容改变时重绘；捕获／取消／长身份／拖动／订阅关闭的离线检查已执行，桌面输入仍待实机。
- 现有控件绘制仍局部耦合 Lua 运行时状态，复用不等于已经有可直接调用的通用渲染器。只提取当前用到的能力；保持旧组件外观／事件兼容，未需要的控件不迁移。
- 旧 WinUI 面板的行为与离线夹具可作迁移对照，但旧 XAML 树断言不能证明新原生实现。离线入口必须切换到生产原生模型与绘制；有效断言迁移，已删除行为的断言删除。
- 媒体条已按单行修改；电池绿色填充、当前日／选中日区别、长列表／低高度适配、权限提示与拖动反馈已接入，浅深色生产图已检查；硬件、桌面观感不以夹具代替。
- `DesktopBackdropCompositor::SetPanelTransform` 的提交路径已同步玻璃窗口区域，已有自有隐藏窗口的动画区域回归；桌面玻璃观感仍待验，不能仅凭区域检查称毛玻璃已全面修复。
- 状态栏和原生面板已接自绘 Tooltip，稳定目标同步文本并保留悬停期限；音量请求中目标与完成回读分开，最新任务 ID 防止迟到回执覆盖。未验证实际滚动观感。
- 主题编辑器已迁至状态栏设置、主题页保留链接；场景配置／IPC／每屏运行时与合并 Dock 文字已接通，不增加右键主题入口。Task View 专用状态沿用已有 Hook 可观察边界，不为此开启任务栏美化。
- 托盘集中改动已落盘：完整 MODIFY 补采、GUID 身份保留、经典 overflow 补采、代次恢复、附近菜单短时纠偏；用户四个应用均未实测，不标为已修复。
- 新 Lua 控件公共 API 没有变更；缺失的 Lua 系统控制写任务不应在文档中标为已完成。
- 54 的稳定性收尾：确认框退出前使旧模型失效，阻止旧回调提交；图形恢复释放并重绑面板／提示设备引用而保留 AppBar；媒体异步等待复用可取消的总预算；设备采样／执行回读／释放共享来源互斥并优先处理就绪控制任务。同步 COM／驱动调用的硬截止仍不保证。

## 5. 有效而克制的验证

| 时机 | 实际工作 |
| --- | --- |
| 开发中 | 代码和调用链检查；仅在协议、所有权、取消、滑条回读等有明确失败信号的高风险点运行定向检查。不为排版、每个按钮或每次改色重跑构建／完整测试。 |
| 第一集中候选接线完成 | 先预检宿主和 Hook 占用，统一运行 `scripts/build.bat`；只在确有占用时按仓库规则告知并 `--reload-shell`。编译／链接警告在本轮处理。成功后先保存独立 `try` 再继续修改。 |
| 一次视觉检查 | 同一生产入口导出栏体及四类面板，挑选浅／深／高对比、代表性 DPI、长文本／长列表、禁用和空状态；核对实际 PNG 与布局边界，不机械组合所有维度。 |
| 关键逻辑检查 | 目标身份／捕获取消、切换队列与销毁、动画区域、Tooltip 原位更新、主题 IPC 往返、托盘协议和重连、订阅释放。优先扩展已有目标，不为数量另建测试程序。 |
| 稳定交付 | 跨模块变化完成一次绑定最终输入的 `scripts/test.bat full`；后续只有相关输入变化、失败或新风险才补跑相应范围。不把旧版本的全量通过称为新实现通过。 |
| 资源评估 | 用相同有效场景记录私有提交、工作集、线程、句柄、采样时间；打开／切换／关闭后的资源回落与闲置唤醒。早先 debugger 暂停导致超时的采样不能作性能结论；400 MB 不等于全由 WinUI 引起。 |
| 必须实机 | 桌面 AppBar、多屏全屏、合并 Dock、微信／PowerToys／WPS／抖音、真实 Wi-Fi／蓝牙／亮度、玻璃观感及 AMD 对照。集中列给用户，不能靠枚举／自动操作桌面宿主冒充验收。 |

不在本轮编排大量基准工程、全量变异扫描或重复离线图片。也不预先承诺固定的内存降低比例。

## 6. 后续维护方式

- 本文保留当前产品边界、依赖顺序和未完成项；历史构建、提交、失败证据继续追加到 `STATUS_BAR.md`，不要把历史中“已通过”直接复制到新实现。
- 后续反馈先归入对应层：需求变更、输入／生命周期、托盘协议、设备后端、布局、设置、采集。只有改变共享边界的反馈才调整架构，普通布局问题在业务层处理。
- 一批完整实现后集中构建和验收；通过的代码尝试按仓库规则独立 `try` 保存，实机结论另记 `verify`。任务整体仍未完成。
