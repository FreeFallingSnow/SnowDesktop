# 目录扫描调度约定

`MenuService` 的默认库存读取使用 `CatalogueForegroundDemand` 控制扫描；直接调用普通
`ReadCatalogue` 保留原有并发，不作为后台限流入口。

- 类型关联和文件注册扫描的并行阶段，纯后台工作使用一个工作线程。小库存保留串行路径。
- 前台菜单、检查或执行需要结果时，控制器直接通知等待者，补足原有按逻辑处理器计算、最高
  八个工作线程的上限。需求在本次扫描的各阶段保持，下一次纯后台扫描重新使用一个线程。
- 默认后台读取检查各显示器上的可见全屏窗口。沿用平台的窗口可见性、客户区覆盖、最大化、
  桌面窗口和系统覆盖层排除规则；不按进程名识别游戏。
- 全屏状态最多每 250 ms 检查一次。暂停发生在当前扫描单元结束后的检查点，队列索引及已经
  读取的结果保留；退出全屏后续扫。前台需求直接解除本次暂停并恢复原有并发。
- 暂停时间从扫描等待预算中扣除。关闭服务时必须先取消并唤醒扫描，再等待工作线程和 future
  收尾；停止后的调度器不得重新启动扫描。取消结果不能作为完整库存发布。

控制器回归与私有注册表库存检查位于
`tests/shell/shell_catalogue_registry_handle_tests.cpp`。原生全屏观察夹具只能显式调用
`SnowDesktopShellContextMenuInvokeTests --fullscreen-scan-fixture`；其窗口位于现有窗口之后，
保持原有焦点，并在十秒后销毁自身。它用于检查宿主的全屏观察及暂停/续扫日志，不代替游戏
或桌面菜单交互的人工验收。
