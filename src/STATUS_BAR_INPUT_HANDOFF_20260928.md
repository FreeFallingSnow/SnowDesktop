# 状态栏输入交接与任务视图崩溃（2026-09-28）

## 现场与结论边界

- 用户复现：高频操作状态栏后先失去点击响应，随后 Dock、桌面及外部托盘菜单也不响应；任务视图、通知切换可能参与触发。用户另确认高频点击任务视图会使 Explorer 重启。
- 本机 Application Error / Windows Error Reporting 在 22:01、22:27、22:31 记录了 Explorer 的实际崩溃，区别于本轮明确执行的 Shell 重载。异常为 `0xc000027b`，WER 报告 `80070057`；22:31 转储落在 `Windows.UI.Xaml.dll`，调用栈包含 `twinui_pcshell` 的界面线程。
- 22:31 转储只包含一份 SnowDesktopTaskbarHook，不能将此次崩溃直接归因于之前观察到的多份旧扩展。同时，没有本项目函数的直接故障栈证据，不能仅凭扩展已加载就认定崩溃来自扩展。
- 22:21 开始的外部状态记录没有使用调试器；用户随后报告不响应。记录中主 UI 线程 CPU 时间仍推进，不能把鼠标不响应等同于主线程整体停摆。相关 Shell 快捷键输入被系统接受，也不等于 Shell 界面成功完成切换。
- 本日较早的一次 `cdb -pv` 取栈会暂停目标线程，可能加重现场卡顿，已向用户说明并停止这种取栈方式；后续使用外部只读状态采样及既有崩溃文件的离线分析。
- 两次进程重开是否由用户手动触发不确定，不作为自动重启缺陷的证据。已保存的崩溃文件没有包含完整 stowed exception 对象；符号下载受网络影响，暂不能定位到引发参数错误的原始调用。

原始证据保存在本机忽略目录 `.codex-probes/statusbar-hang-20260928/`：`shell-crash-events.txt`、`explorer-2231.dmp`、`explorer-2231-raw.txt`、`handoff-222147.jsonl`、`reproduced-2223.log`。转储、用户日志及临时采样脚本不进入提交或发行包。

## 本轮候选调整

1. 快捷搜索因外部激活关闭时，不再调用强制恢复桌面前台的路径；切换到已排队的新面板也不经过一次中间桌面激活。只有主动关闭、搜索仍拥有前台、没有后续交接时，才允许恢复桌面焦点。
2. 任务视图发键后独立记录一次正在进行的系统切换。重复任务视图及其他原生面板请求在此期间被丢弃，不排队补发，也不因普通激活请求取消而清除保护。等待预期的显示／关闭通知及短暂动画稳定时间；没有通知时 1.5 秒到期释放，Explorer 重启或完全未发入输入时立即释放。
3. 无电池时移除状态栏／控制中心的电池占位；不可用的音量、亮度显示状态说明，缺少无线／蓝牙硬件时去掉无效展开箭头；Win10 不支持原生控制中心时，底部电源按钮靠右排列。

这些是独立于现场结论的代码调整，**尚未验证全部点击阻塞或 Explorer 崩溃已解决**。任务视图保护只约束本应用入口，不拦截用户直接按 Win+Tab。Win10 USB 移除及 Windows 安全中心托盘右键问题仍单独待排查，本候选没有改写托盘回调协议。

## 验证范围

- 规则检查覆盖搜索失活／主动关闭／等待交接时的焦点恢复条件。
- 任务视图检查覆盖连续点击只接受一次、开关分别等待对应通知、过期及重复通知、缺失通知的超时、Explorer 重启清理，以及其他原生面板不能在切换中插入。
- 生产面板离屏检查覆盖无硬件、权限受限仍可进入、无电池占位、不支持的亮度／音量，以及能力恢复后重新显示操作。
- 原始桌面、外部通知及任务视图场景需要实际用户反馈，以上检查不能替代。开发中的待验证候选仅执行相关测试，不重复运行无关全量。
