# 构建与验证

长期测试的准入、临时验证及全量触发条件以 [根规则](../../AGENTS.md#临时验证与长期测试准入) 为主要定义。组件包同步另见 [组件包与分发](widget-packages.md)。本说明用于选择实际检查、组织场景和限定证据结论。

## 构建与激活

- 最终 Release 验证使用 `scripts/build.bat`；脚本、CI、IDE 配置以 `CMakePresets.json` 为共同来源。Preset、Ninja、直接 CMake 仅用于诊断；定向编译须写清目标名。
- 独立候选使用标准入口编译，输出占用预检依据实际编译目录。完整产品构建成功并保存运行文件后，激活阶段更新本检出的 `.build/Release`：原先运行则正常退出、替换清单内文件、恢复参数及运行状态；原先关闭则保持关闭。保留 `data/`、`data.debug/` 及旧运行文件备份，激活失败单独按回执报告。后续测试失败不撤回已交付构建；Explorer 和其他目录应用保持运行。误判而提前退出应用时恢复原状态并核对进程。
- `--reload-shell` / `-ReloadShell`、`--close-application` / `-CloseApplication` 仅用于旧协议或确实覆盖已占用运行目录。执行者取得执行权、核对输出路径及进程身份、告知副作用后才能使用；只需退出应用时不重启 Explorer，不终止未知进程。阻断时保留证据，核对实际入口及输出目录。
- 所有自有发行 EXE 含完整 `VERSIONINFO`：文件/产品版本、产品名称、公司名称、用途明确的文件说明、内部名称、原始文件名。版本只来自 `version.json`；新增目标复用 `cmake/SnowDesktop.VersionResources.cmake` 中的 `snowdesktop_add_executable_version_resource(<target> "<用途说明>")`，已有专用资源可保留。主构建和独立辅助构建均接入配置末尾检查，缺失完整资源时报错。测试输出留在 `tests/`，第三方保留上游身份；交付核对实际生成与整理后文件属性。签名与误报另按实际证据记录。
- 警告修复按根规则执行：修正源码、包含顺序、兼容边界、生成输入或构建接入，不能直接改生成文件掩盖。重编核对原警告消失及新增警告；最终交付仍完成所需标准构建。

## 开发闭合与检查选择

1. 以本批已明确需求和缺陷为开发单元。计划内功能、必要修正及整合全部完成，接口与布局稳定后进入交付验证；待实机仅列确需用户或外部环境验证的项目。
2. 开发中优先走查与最小充分定向检查。只有具体编译诊断、明确失败或下一步实现依赖结果时提前检查，并说明所回答的问题。布局、字号、间距和文案不逐项编译、全量、批量导图或新增实现复述测试。
3. 新反馈使受影响部分回到开发阶段。验证范围由本批实际影响确定。用户要求集中实现或停止追加测试时按指定顺序执行，记录欠缺验证。
4. 冻结前沿修改入口核对直接/传递依赖、调用方、事件接收方、数据读写方及运行资源，选择全部相关项目；影响不明先补映射并扩到相关模块。全量按根文件的明确条件选择并记录依据。

| 变更或阶段 | 所需检查 |
| --- | --- |
| 纯文档、注释，运行及生成结果不变 | 差异、链接、相关静态检查；无需宿主构建或全量 |
| 纯 Lua 组件包 | 组件级检查与真实加载来源核对；越出包边界重新判断 |
| 普通迭代、待实机候选或模块局部交付 | 必要编译、全部受影响的回归/集成测试、原场景验收 |
| 公共 API、跨模块、迁移/所有权/权限、OLE 生命周期、异步调度、构建测试设施 | 沿调用链选择相关目标及集成测试；全量按根文件条件选择 |
| 局部测试调整 | 运行受影响条目，新增回归确认失败信号，删除说明替代覆盖；公共运行器/选择器/登记变化沿依赖处理 |
| 维护者 PR 或等价整合 | 最终输入的相关检查及受影响功能验收；相同输入的有效本地/CI 证据可复用 |
| 最终发布候选 | 标准 Release、应用全量、核心实机验收绑定最终候选；包装后核对包内容、版本、安装/便携形态 |

- 全量失败后保留原报告，只补失败项与修正影响项。分别记录原失败、修正、定向命令及复用范围，保留输入未变的有效通过结果。
- 环境、工具启动、基础设施阻断与产品缺陷分开。诊断有界且有停止条件；无法及时解除时保留限制并继续独立工作，不反复全量、扩大到无关排查或调整用户系统配置。

## 长期测试的运行设施

- 正式测试的源码、驱动及断言使用 C++；被测工具保留自身语言，必要进程/协议/数据夹具不能代替 C++ 验收断言。`SnowDesktopTests` 是测试程序的唯一聚合清单；应用、工具、核心、快速分组及筛选构建均由同一 CMake/CTest 声明和标签派生，不在脚本复制清单。
- 标准入口 `scripts/test.bat` 无参数仅显示用法。`name <regex>` / `label <regex>` 定向选择；`core` 选应用核心，`fast` 另排除 `integration`，`full` 选应用全量；三者均排除 `tools`、`manual`。`tools` 单选构建工具回归，应用与工具分别报告覆盖。
- 协作、计划、筛选、PowerShell 启动、等待、重试、共享资源和看板属于 `tools`。普通应用聚合不依赖工具目标，仅工具回归不编译整套应用测试；计划中使用 `-Suites tools` 或明确测试名，可与应用需求合并并分别记覆盖。
- `manual` 为显式按需诊断，`name/label` 可选、`list` 必须显示；手动诊断结果单独报告。一次性排查优先使用忽略的任务目录，长期诊断仍须符合测试准入规则。
- 选择集合必须非空且充分，按实际影响核对 `core/fast` 或正则选中集合。六项必需工具回归不能因依赖缺失被移出清单；阻断、零执行和未运行不得报告通过，不自动安装依赖。
- CTest 默认并行，并行度来自 `CMakePresets.json`。隔离临时目录、端口、日志、用户数据；共享桌面、Explorer、宿主输出等声明 `RESOURCE_LOCK`，确实无法隔离才 `RUN_SERIAL`。不将整套串行化或用盲目并发/延长超时代替隔离。记录实际并行度、总耗时、失败与未运行项。
- 真实环境端到端条目标记 `integration`，不进 `fast`。异步检查采用有界条件等待及可控完成顺序，避免固定睡眠；覆盖所测生命周期相关的取消、销毁、交错及部分失败。
- 自动重试只由批次运行器按已审查白名单、结构化故障、有限次数与退避执行，校验输入并保留首次失败及 flaky 标记；未覆盖故障交接，不由模型盲目重跑到绿。不稳定场景应消除不确定性，或按其持续价值决定删除。

## 补验与证据复用

- 补验前查既有批次、报告及 `.build/verification/`，核对测试程序、运行依赖、被测输入与资源。有效通过结果直接引用，同项正在运行只等待或协调；陈旧 `running` 核对进程和日志后确定处理。
- 程序和依赖已生成且匹配输入时，只执行明确选中条目；源码/依赖改变、产物缺失或身份不明才重新编译。

  > 例如，使用 `ctest --test-dir .build -C Release -R "^widget_author_tools$" --no-tests=error --output-on-failure` 做纯执行补验；`scripts/test.bat name/label` 会附带构建。

- 独立补验使用唯一 `.build/verification/<runId>.json` 与独立日志，先记 `running`，结束记 `passed/failed/interrupted`。记录任务、名称、命令、配置、二进制/资源指纹、输入匹配依据、起止时间、退出码。日志冲突时隔离运行目录，或按清单原参数、环境、工作目录和超时直跑程序；不操作用户文件或 `.build/*/data/`。
- 持久补验、订阅/取消、`-Fresh`、原生文件审阅及引用凭据按 [脚本手册](../../scripts/README.md) 执行。已结束结果引用保留原观察与独立凭据，并完成当前输入及依赖闭合审阅；报告其实际引用范围。
- 可复用须同时满足：前次通过、输入及选择规则不变、无未解释的不稳定失败、证据可追溯。绑定提交与未提交内容、被测/测试源码、传递依赖、生成输入、资源、工具链/SDK、开关及环境；实机再绑定运行宿主、组件来源与原始样本。
- 用户要求重跑或怀疑缓存时实际执行相关检查。源码输入变化只使受影响结果失效；只改提交说明或无关文档不使运行结果失效。实时网络/系统证据注明环境边界。
- 分别报告本次通过、引用有效结果、失败、未运行、环境阻断、待实机；一次有效全量指同一有效输入的一次实际通过。
- 启用通用自动依赖选择或跨候选缓存前，须核对 CMake/CTest、构建依赖、运行资源及语义风险，处理增删改名及未跟踪输入；先建议模式与全量对照，以已知缺陷/受控变异检验漏选。未知影响扩大相关检查；选中及执行集合均须非空。
- 配置、增量编译、执行、产物核对和实机准备分开计时；先消除重复、固定等待及无效数据，再隔离资源和提高并行。昂贵扫描单设预算，性能结论附实际测量。

## 行为回归的设计与评估

- 先根据用户操作、需求、稳定契约和原始样本确定输入与独立预期，再选入口。预期独立于被测实现确定；更新快照/黄金文件须有行为或契约依据。
- 新增/改写时说明具体风险、生产入口、替身边界、预期和确定失败信号，可写于名称、短注释或提交，无需逐断言模板。缺陷位于宿主路由、调度、生命周期或最终提交时，必须执行该环节与可观察结果；提取入口须让产品与测试共用真实路径。
- 网络、系统失败、时钟和完成顺序可用替身；保留被测调度与提交的生产实现。替身直接给最终结果时，只报告实际验证的调用/转发层。局部测试有独立价值可保留，但名称及结论限定该层。
- 对可自动化缺陷，先运行目标输入并等待退出，观察业务错误失败，再以相同输入验证候选。已有修正可在隔离副本恢复原错误。有效发现须执行到目标错误位置并由业务断言失败。

  > 例如，负向对照若因编译失败而退出，记录为对照未完成；待程序正常执行后再观察目标业务断言。

- 关键新增、漏测调查或断言改写做定向负向对照，优先恢复原始路由、数据流或提交错误，按风险选择对照范围。

  > 例如，恢复错动作、漏提交或提前删除来源，检查对应业务断言失败。

- 按条目及用例评估风险、真实入口、替身、预期、失败证据、成本，记录保留/增强/改写/合并/删除依据。重复而无新增风险、只复述实现/排版/无语义顺序、只检查框架自身、功能已删、长期跳过或无确定信号的测试应删除或改写。静态护栏遵守根文件准入例外并归一化换行；执行、并发和阻塞结论使用行为证据。

  > 例如，注释中的函数名即可让正向检查通过时，改为行为检查或收窄为明确的静态护栏。

- 评估结论列明实际检查范围。恢复目标错误后仍通过时，保留原场景与失败证据，记录并处理覆盖缺口。发现非测试产品问题，按 [Issue 规则](delivery.md#bug-与-issue) 留证；评估任务不顺带修改生产行为。

### 缺陷证据

同一故障或结论记录一次，可引用既有提交、Issue 或验证记录。

| 项目 | 内容 |
| --- | --- |
| 故障与预期 | 触发条件、原始/等价输入、用户可见错误、需求或契约依据 |
| 生产路径与替身 | 实际入口、路由、调度、提交；替换依赖与直接提供的结果，缺陷环节是否真实执行 |
| 原错误失败 | 旧实现/隔离负向对照、命令、退出码、业务断言和日志；缺失则说明原因 |
| 候选结果 | 同一输入的命令、结果、日志及源码/二进制/运行资源身份 |
| 缺口 | 未运行、环境阻断、无法自动化或待实机项目，以及证据支持的结论范围 |

缺少生产路径或原故障失败证据时，报告已完成的局部检查及覆盖缺口；继续独立工作并按 `try`/Issue 状态推进。

## 核心拖放矩阵

先确定产品行为范围，建立整体矩阵，再映射旧测试及生产入口、安排逐路径接入。已知 Bug 可作资料或优先回归；扩展边界见根文件。

| 因素 | 范围内需盘点的风险 |
| --- | --- |
| 来源/目标位置 | 桌面、Dock、弹出面、外部程序及进出方向，分别建模 |
| 容器与表示 | 集合、桌面文件、映射、集合组、文件组、Lua 逻辑槽位；组件本体/图标/标签、展开、活动成员、固定/映射、可见/锁定/可用状态独立表示 |
| 载荷与选择 | 文件/目录/快捷方式/逻辑引用/组件/标签/虚拟文件/图片/文本/URL，区分容器与成员；单多选、混选、多来源、捕获顺序、稳定身份及容量边界 |
| 关系 | 同实例/同类型跨实例/跨类型，同目录/跨目录、同卷/跨卷、重复引用、自身、父子 |
| 手势与能力 | 发起按键，开始/悬停/释放修饰键及变化，右拖菜单选择/Esc/外点取消；来源效果、目标能力、只读/权限、容量及自动收纳 |
| 命中与落点 | 空白/占用格/条目/本体/标签/缝隙/翻页边缘，屏幕/页面/网格/索引，多屏和 DPI |
| 排列与传输 | 手动、排序字段/方向、分组及刷新顺序；内部/OLE/往返、路径/Shell/延迟提供、同步/异步及所有权存活期 |
| 时序与环境 | 成功/取消/失败/部分完成、连续和交错任务、等待时源/目标变化或销毁；路径、文件系统、权限等会改变行为的环境 |

- 输入因素和验收分开。移动、复制、链接、逻辑归属、组件移动、合并、建组、释放和排序各自定契约；按产品约定分别确定各上下文的修饰键含义。菜单提供动作属于预期，用户选择属于输入。
- 每条契约确定接受/拒绝、提示/菜单、提交次数、来源保留/移除、输出内容/链接目标、稳定身份/归属、位置/顺序及刷新重载结果；核对预览与提交一致性，图片实际解码，连续异步请求保留独立落点。取消不执行未选动作，部分失败按明确成功集合与策略验收，不假设全成功或自动回滚。
- 关系标为支持、应拒绝、结构不适用、行为待定义。支持与拒绝均须有产品依据；约束仅排除结构不适用，应拒绝和非法输入仍验证无错误副作用，待定义不能默认通过/拒绝/跳过。
- 范围内先列因素域及约束，再按风险选组合；核心/已知缺陷显式覆盖，其余按有依据的等价类、边界及组合强度减少重复，组合强度依风险确定。时序另建序列；新类型/状态/动作/修饰/传输先分类并定预期，不用默认分支或当前输出快照消除缺口。
- 映射分别注明规则、路由、文件提交、布局持久化和实机边界；整体覆盖按实际行为与执行边界记录。待定义行为与尚未接入测试分开列出。
- 当前产品矩阵与已确定行为见 [拖放行为说明](../../tests/drag_drop/README.md)；组合强度方法参考 [NIST FAQ](https://csrc.nist.gov/Projects/automated-combinatorial-testing-for-software/faqs)。

## 实机验收

- `fix/feat/perf/verify` 前取得与所声称结果相符的实际证据。视觉、交互、兼容性使用用户原始对象/场景或等价可观察证据；未验收的已编译修改按提交规范及时保存 `try`。
- 桌面宿主自动化限制见根文件。UI 由用户实测时，仍完成可稳定自动化的路由与数据结果检查；缺少入口时明确记录接入工作及覆盖缺口。用户实测反馈可按 `verify` 记录。
