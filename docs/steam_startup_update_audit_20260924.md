# Steam 启动与更新流程审查（2026-09-24）

## 范围与结论

审查基线：`6f04fd21d748e3bafd6e27c1a297f7ec43af7590`，`release/v1.0.7.0`。
本轮为流程审查与隔离复现，未修改生产代码、发布包或用户数据，未登录 SteamCMD。

确实存在过度验证，但也存在更重要的状态转换问题：清理入口会再次更新；发布完成被当作可以切换当前版本的依据；旧版本清理早于宿主初始化成功。完整性检查不能证明新宿主能启动。优先修正这些边界，再合并重复检查。

此前 exFAT 候选 `6f04fd21` 已把锁文件及刷盘文件的 `FileAttributeTagInfo` 查询换成基础句柄属性查询，并记录底层错误。用户确认的是原版本移到 NTFS 后能启动；新候选在原 exFAT 环境仍待验证，见 [兼容性记录](steam_runtime_exfat_validation_20260924.md)。

## 发现与关闭条件

### START-01 / P1：清理命令会激活未启动的新版本

位置：`src/steam_launcher_main.cpp:203`、`:212`、`:218`；`src/main.cpp:248`。

`--snowdesktop-launcher-prune-only` 先调用 `ApplyDistribution`，再把其结果当作当前宿主传给 `PruneInactiveRuntimes`。主程序没有向清理进程传递自身版本身份。因此两次操作之间分发变化时，清理进程可以选择与调用方不同的版本。

**已复现：**使用实际 Release 启动器，在隔离目录先准备 A，再将分发清单改成 B，只执行 `--snowdesktop-launcher-prune-only`。退出码为 0，指针由 A 变成 B，未占用的 A 被删除，期间没有启动 B。安装根目录 `data/keep.txt` 保持原样。实际运行中的 A 是否因映像/文件占用而保留，取决于占用；不能把占用当作版本身份保护。

修正方向：清理入口不得执行更新或切换指针；绑定发起清理的宿主身份并在锁内重新核对。不再当前时应停止清理。清理只处理符合保留策略的旧版本。

关闭条件：A 运行期间分发改为 B，A 发起清理仍不能激活 B；指针发生并发切换时不能清理请求方或受保护版本。增加真实 CLI 入口回归，不能只测试管理器函数。

### START-02 / P1：缺少启动失败回退，清理时机过早

位置：`src/steam_runtime_manager.cpp:1544`；`src/steam_launcher_main.cpp:150`、`:236`；`src/main.cpp:380`、`:543`、`:569`。

指针在创建宿主进程前提交。`CreateProcessW` 失败时只报错，不重试先前可用版本；创建成功后启动器不观察宿主启动结果。宿主取得主实例资格后，先请求清理，再安装崩溃观察器、进入 `DesktopApp::Run`，此时数据迁移和 OLE 等初始化尚未完成。旧版本因此可能在新版本初始化失败前被删除。

**边界复现：**实际 Release 启动器启动一个写出结果后立即 `return 13` 的无界面替身，启动器返回 0，没有 `launcher.log`，指针保持新版本 B。替身直接运行的对照退出码为 13。该复现证明启动器不确认子进程启动结果；不是对真实桌面宿主崩溃的实机验收。清理早于初始化、创建进程失败后无回退由代码调用顺序确认。

修正方向：区分“已准备”“待确认”“已知可用”版本，保留一个已知可用版本到新宿主确认可用以后。失败必须记录原因并给出恢复路径。不能直接用“进程存活若干秒”或“退出码非零”替代协议：正常单实例退出、用户取消接管和数据已迁移后的降级均需分别处理。

关闭条件：覆盖创建进程失败、初始化立即失败、接管取消、成功确认，以及确认前清理请求。失败时保留可恢复的版本和数据；涉及数据格式升级时明确能否安全降级。

### START-03 / P2：重复整包哈希随清理重试放大

位置：`src/steam_runtime_manager.cpp:940`、`:1610`、`:1641`、`:1668`、`:1706`、`:1767`；`src/steam_launcher_main.cpp:215`。

对管理器的隔离源码副本只增加 SHA-256 调用/读取字节计数，保留原来的文件操作、哈希和 CLI。2 个载荷文件合计 327,168 字节，实测：

| 路径 | 哈希调用 | 哈希读取字节 | 等效整包次数 |
| --- | ---: | ---: | ---: |
| 首次准备 | 8 | 1,308,672 | 4 |
| 复用已有有效版本 | 2 | 327,168 | 1 |
| 无旧版本的清理命令 | 4 | 654,336 | 2 |
| 旧文件持续被真实只读句柄占用的清理命令 | 82 | 13,413,888 | 41 |

首次准备的四遍分别为分发源、逐文件复制后的目标、完整暂存版本、重命名后的版本。正常主实例的“复用 + 主程序触发清理”路径合计三遍；不是每次重复点击已有实例都三遍。占用场景清理耗时 10,629 ms，包含 40 次固定 250 ms 等待，最终保留旧版本并记录日志。

本机已有打包快照 `1.0.7.0-bb4e5b2d1ea4f3cd` 共 404 文件、145,973,554 字节。按上述次数换算，三遍为 417.63 MiB，41 遍为 5.57 GiB **逻辑哈希读取量**；这不是实测物理磁盘流量或用户启动耗时，缓存会影响实际 I/O。

修正方向：清理不重新应用更新、不在每次重试中校验活动版本的全部内容；一次事务复用已获得的验证结果。复制后的内容验收与元数据/目录发布检查分开，避免对同一暂存内容连续重算。首先保留一次有意义的内容检查，不以仅比较时间戳替代内容完整性。

关闭条件：对真正执行的 SHA-256 字节数建立上限；持锁重试、活动版本切换和完整性损坏仍有确定失败信号。分别测量准备、普通启动和清理，不能把整个流程的时间归给某一次属性查询。

### START-04 / P2：普通附加文件也会取消有效版本的回退资格

位置：`src/steam_runtime_manager.cpp:703`、`:724`、`:924`；`tests/steam_runtime_update_tests.cpp:1349`。

运行目录要求文件/目录集合及路径大小写与清单严格相等。该检查会将多余 DLL、普通说明文本、空目录和历史 `imgui.ini` 一并判为无效。

**已复现：**有效版本 A 增加 `notes.txt`，同时使分发源的 `payload.bin` 大小不符。实际 Release 启动器返回 1603，日志为分发文件大小错误、回退因 `notes.txt` 被拒绝。只移走 `notes.txt`，保留相同的损坏分发，重新执行返回 0。原运行载荷内容未变化，根目录用户数据未变化。

修正方向：区分可能影响可执行文件、DLL、脚本、插件或资源发现的附加项，与确认不参与加载的残留。清单要求的文件完整性仍须保留；不能简单允许任意未知 DLL/脚本。对可确认无害的残留优先告警或保留，而非阻断回退。大小写与元数据文本格式是否需要严格相等，也应按实际消费语义判断。

关闭条件：普通文本残留不妨碍有效版本恢复，真实可加载的污染仍被识别。现有测试明确要求普通文本也被拒绝，需同步改成用户可见行为回归；保留那些“测试通过”不能证明策略合理。

### START-05 / P2：当前指针是唯一恢复入口

位置：`src/steam_runtime_manager.cpp:1422`、`:1474`。

**已复现：**保留完整有效的运行目录 A，移走 `current-runtime.txt`，使分发清单无效。实际 Release 启动器返回 1603；恢复指针后，相同无效清单下返回 0。当前实现不搜索已发布版本，也没有独立的已知可用版本记录。

这是一项恢复能力缺口，不代表应该忽略无效指针或随便运行目录里的 EXE。修正时应与 START-02 的已知可用记录一起设计；可恢复候选仍需所有权、完成状态、内容和兼容性检查，不能按目录字典顺序猜测最新版。

关闭条件：指针丢失/截断且分发暂不可用时，可以从可靠记录恢复；没有可信候选时给出准确诊断并保护全部用户数据。

### START-06 / P2：版本未变也强制重写指针

位置：`src/steam_runtime_manager.cpp:1553`、`:676`。

**已复现：**对已经指向 A 的指针保留不共享删除的只读句柄，再复用 A，仍尝试替换指针并报 Win32 5，随后再次全量校验 A 作为回退。最终退出 0，但同一份有效载荷被哈希两遍，日志出现“cannot publish state file”。

修正方向：锁内确认所选版本与现有指针相同且指针有效时，不重复写入。需要切换时再进行原子替换和必要的有限重试。此项本次并未造成最终启动失败，不能与用户最初的目录发布失败混为一谈。

关闭条件：无变化启动不写指针、不因只读占用产生伪更新失败；实际切换仍能处理真实失败并保持可恢复状态。

### START-07 / P3：转发参数会丢失空字符串

位置：`src/steam_launcher_main.cpp:28`、`:114`。

**已复现：**传入 `--probe "" tail`，无界面替身收到 `argc=3`，参数只有可执行路径、`--probe`、`tail`。空字符串被 `QuoteArgument` 原样返回为空，没有写出 `""`。

修正方向和关闭条件：正确引用空参数，增加实际子进程参数回读，覆盖空值、空格、引号及末尾反斜杠。尚未发现其影响当前常规 Steam 启动参数，优先级低于恢复流程。

## 哪些检查应保留

| 检查 | 必要性及放置位置 |
| --- | --- |
| 独占更新锁 | 防止并发发布/清理互相破坏，保留；清楚区分打开失败、类型检查失败和竞争超时 |
| 路径越界、目录/文件类型、删除目标的重解析点与所有权 | 防止读写或清理到错误位置，保留；属性不是锁本身，也不需要查询未使用的标签 |
| 清单要求的文件与内容完整性 | 防止半包、损坏载荷被启动，保留；减少同一事务中的重复全量读取 |
| 暂存发布、完成标记、原子选择 | 保留；完成标记证明准备完成，不能证明宿主初始化成功 |
| 对任何额外文件、大小写和 JSON 原始字节的严格等同性 | 不能一概视为启动必要条件；按加载语义评估，普通残留不应与可执行污染混同 |
| 活动版本清理重试中的整包哈希、无变化的指针写入 | 属于可以移除的重复工作，不提供与成本相称的新证据 |

建议顺序：START-01/02 的身份与成功确认边界 → START-03/06 的重复工作 → START-04/05 的兼容与恢复策略 → START-07。改变内部清理参数或成功确认协议时，还须核对旧启动器与新宿主混合更新的兼容性。
