# Windows 自动隐藏任务栏与底部 Dock

## 目标与当前状态

保留用户触边、任务栏点击及键盘唤起；避免窗口最小化等被动激活导致任务栏展开并遮住 Dock。
当前候选只增加诊断、删除强制移开光标的旧防护，**尚未过滤任何任务栏展开请求**。
诊断复用现有任务栏外观 Hook 的加载条件，因此关闭所有外观规则时不会安装此观察器。
本轮不更改外观设置、不新增用户入口，也不改变最小化命令或动画覆盖窗口。

## 已有证据与解释边界

2026-09-17 的原场景日志显示：普通窗口最小化后，前台先转到 `Shell_TrayWnd`，
随后自动隐藏任务栏从屏幕下缘向上移动；当时光标未到屏幕底边。也观察到非 Dock 发起的
最小化出现类似序列。因此强制移开边缘光标无法处理该触发路径。

最大化窗口的 Dock 动画覆盖窗口会覆盖整个显示器；已有日志中它伴随任务栏暂时失去
topmost，任务栏在动画期间保持隐藏。这与 Shell 的全屏避让机制相符，是“最大化最小化
不触发”的高可信解释，但不是所有 Windows 构建的保证，也不能用它代替展开原因过滤。
目前保留该覆盖窗口行为，避免先移除现有保护效果。

参考：[微软关于全屏识别与 NonRudeHWND 的说明](https://devblogs.microsoft.com/oldnewthing/20250522-00/?p=111211)。

## 原生观察器

对本机 x64 `Taskbar.dll` 离线读取微软公开 PDB 并检查反汇编，发现主、副任务栏处理
`WM_ACTIVATE` 时调用各自的 `Unhide(0, 8)`。这个 `8` 是此模块的原生请求值，
不能等同于其他模块（如 `Taskbar.View.dll`）中编号相同的原因枚举。

适配身份为 `Taskbar.pdb` GUID `BC068C70-D2B5-878D-1FBB-AFD6824EC5D2`、age 1，
PE 时间戳 `0x01dffebf`、映像大小 `0x308000`；入口 RVA 为 `0x924c0` 与 `0x14cca8`。
只有身份及入口字节全部匹配才安装 MinHook 观察器。其他构建保留消息观察和系统原行为。
观察器直接调用原函数，不丢弃 `WM_ACTIVATE`，不改变参数、返回值或任务栏位置。
该 PDB/ABI 校验是支持范围约束，不是跨 Windows 版本的符号适配方案。

日志前缀为 `[TaskbarAutoHide]`，包括激活前后、原生展开调用、单调时间、调用线程、
任务栏/前台/前窗口句柄、最小化状态、矩形、光标及调用点 RVA。不采集窗口标题或内容。
`adapter flags=1` 表示双入口安装成功；负值表示不支持或安装失败，继续原行为。
`taskbar=0` 表示该次原生调用不在被观察的 `WM_ACTIVATE` 调用栈内，不能据此归属于某个任务栏。
丢失记录会单独计数；没有记录不能证明没有调用。

Explorer 只向固定缓冲区写入，忙或满即丢弃，每线程最多每秒 64 条。宿主定时排空并记录日志。
停用控制器或宿主退出后停采；模块与跳板由现有 TAP 生命周期保留到 Explorer 退出。
内部共享内存协议升级为 v7，宿主和 Hook 必须同时更新并重启 Explorer；不改变组件公共 API。

## 验收与后续实现

在同一候选及同一显示器下分别测试普通窗口的 Dock 最小化、标题栏最小化、最大化后 Dock
最小化、主动触边、Win/Win+T、任务栏点击；多显示器还须覆盖副任务栏。记录操作顺序和现象，
对齐宿主 `DockTaskbarTrace` 与原生 `[TaskbarAutoHide]` 的 tick。

下一步只有在实际调用序列确认后，才对已识别的被动展开分支加入过滤，并检查当前 Windows
特性开关是否绕经 `Taskbar.View.dll`。不能把“鼠标不在边缘”单独当作被动请求证明；
也不能吞掉整个激活消息、持续抢前台或事后移动/隐藏任务栏。

最终控制器应独立于外观开关，以底部 Dock 和系统自动隐藏状态控制；支持主动触边、点击、
键盘和辅助功能入口，按监视器处理。无法识别的系统版本或原因保留系统行为，并报告支持状态。
只有过滤实测通过，才单独评估给动画窗口增加 `NonRudeHWND`，消除偶然的全屏避让依赖。
构建和自动测试不能代替上述桌面兼容性验收。
