# 开始页与新手引导

设置导航中的“开始”分为“基础”和“探索”。首次启动完成桌面初始化后打开“基础”；后续通过设置重新进入。用户关闭页面后不会因任务未完成而在每次启动时再次弹出。

## 基础

| 任务 | 操作与完成条件 |
| --- | --- |
| 添加集合组件 | 实际创建集合，记录练习集合的 ID。创建失败不完成；空白页提示组件被替换不影响判定。 |
| 拖入应用图标 | 应用图标实际新增到练习集合中。普通文件、其他集合、重排及仅悬停均不完成。 |
| 移动并调整大小 | 练习集合的位置、尺寸分别实际改变后完成。两个动作可分开进行；取消和无变化不计入。 |
| 添加桌面文件组件 | 实际创建组件即完成；说明可右键开启“自动收集”，引导不自动开启该选项。 |

任务支持“稍后再做”，完成记录在重启后保留；已完成说明仍可展开。主动通过引导重新添加集合会切换练习对象，保留已经学过的操作记录。集合被删除、移入组或 Dock 后，可以重新添加独立集合继续练习。

## 探索

提供文件分类、集合与组的用途、Dock、快捷导航、页面与多屏、外观、组件和备份说明。导航到已有设置入口，不复制其编辑控件。组件页与添加菜单继续按现有可用性和高级功能规则处理入口。

## 状态与调试

- 私有进度文件为 `SnowDesktop.onboarding.json`，与布局分开保存。旧用户缺少此文件时不当作首次启动；首次弹出失败时保留待显示状态。
- “调试 → 临时初始化”使用全新的内存进度，并在初始化切换命令返回后打开“开始 → 基础”。关闭临时初始化或重启会恢复正常用户进度，不合并练习结果。
- 数据损坏时不覆盖原进度文件，诊断日志记录加载失败；当前会话仍可查看页面和练习。
- 私有设置 IPC 传递进度和操作请求；没有新增公共组件 API，也没有修改布局 schema。

## 验证边界

自动回归加入现有 `settings_window_open_rules` 条目，覆盖状态转移、目标身份、部分完成、暂缓、持久化与实验隔离。`winui_home_about_page_presenter` 检查开始页不得直接执行文件操作或桌面修改。完整自动测试不等于桌面交互验收。

本轮桌面和视觉验收待实机，建议使用临时初始化：

1. 开启临时初始化，确认自动切到“开始 → 基础”，四项进度归零；关闭页面后不会自行反复弹出。
2. 添加集合，确认组件出现且第一项完成。另在只有提示组件的空白页重复添加，确认不会误报没有空位。
3. 拖入普通文件、拖入其他集合、取消拖动均不完成第二项；把应用图标放进练习集合后完成。
4. 只移动时显示还需调整大小，只调整大小时显示还需移动；两个动作完成后第三项完成。取消或原地松开不应计入。
5. 添加桌面文件组件后第四项完成；右键菜单中可自行开启自动收集，添加时不会自动开启。
6. 暂缓任务、返回设置、删除练习集合后重新添加，确认仍能继续；结束实验后确认原布局和原进度恢复，再次开启实验从零开始。
7. 使用独立的全新便携目录验证真正首次启动会打开开始页；关闭再启动不重复弹出。不要清理现有用户的 `data`。
8. 检查基础与探索的键盘焦点、浅色/深色/高对比度、放大文字和窄窗口；探索导航打开正确页面，菜单与创意工坊沿用可用性限制。
