## 本轮追加：窗口复用与定位

- 启动桌面指引后，设置进程自行最小化 HWND，不关闭会话、不销毁页面后端。返回指南复用现有窗口并恢复原条目。点击桌面“收起”时发送异步关闭请求，由设置进程重新检查当前是否仍最小化；已被用户还原的窗口不关闭。正常关闭继续执行已有的提交与退出流程。
- 指南打开的主设置、次级设置和 Dock 前置设置均携带本次会话的返回条目。页面顶部显示整行“返回指南 · 条目名称”按钮。返回后移除上下文，普通导航不显示横条。
- 设置定位在目标挂载后滚动。输入焦点仍交给编辑控件，高亮覆盖其完整标签行或所属卡片；叠加层不接收输入、不改变卡片布局，使用主题强调色，随布局与滚动更新。
- 独立设置进程接通宿主的工坊可用性及打开回调。显示与实际打开均检查当前 Steam 桥可用性，不根据发行渠道或缓存解锁状态推断。
- “多页”包含用途、右键新增与管理、边缘点击、拖动停留翻页、键盘翻页。文案说明已有页面、空页占位、末屏分页和桌面键盘上下文等前置条件；复用现有 `pages.svg`，十种语言同步。
- 私有设置 IPC 升至 11，拒绝缺少返回路由字段的旧进程。公共组件 API 不变；仍只保存面板折叠偏好。

- 创意工坊按既有可用性回调显示，点击时再次检查并调用既有打开入口。
- “组件开发工具”复用已有显式开启流程并定位 Agent Skill；不选择 Agent、不安装 Skill、不创建组件。原组件页的“自己开发”按钮与指南共用同一内部开启实现。

## 重复临时初始化反馈（2026-09-16）

`8703a3f7` 之后的用户验收仍未通过，已用 `1c667933` 记录失败：第一次实验没有读取原生布局，之后切换引发设置崩溃，重新打开时临时初始化开关仍开启，关闭后桌面恢复且调试入口消失。

本轮依据及调整：

- 两个原始设置进程转储（PID 28868、35904）都落在 `SettingsShell::FocusPendingTarget + 0x4a0` 调用 WinUI `Focus` 的位置，异常为 `0xC0000005`。引导路由现在选中指定内容并滚动到通用页顶部，不再登记或强制聚焦 SelectorBarItem。普通键盘访问保留；同页跳转也会更新基础/探索选择。
- 主动状态推送与按设置快照请求的状态曾混用独立计数及控制器修订号，后者还会覆盖发布者版本。现在由宿主统一生成完整状态与递增版本，设置侧保留该版本，避免把新状态当作旧值丢弃。
- 从正在进行的实验恢复设置时，调试入口按本次设置会话保留。关闭实验不会移除当前调试页；正常的新设置会话仍遵守原有解锁规则。
- 首次失败日志为 `HRESULT=1`（`S_FALSE`）。原生视图读取针对 `S_FALSE` / `E_PENDING` 在原来的 2500 毫秒预算内等待就绪；永久失败立即返回，预算耗尽仍使用默认布局。不更改 Explorer 图标位置、显示设置或用户文件。失败日志增加阶段和尝试次数；`S_FALSE` 的不完整快照不能当作成功。
