# 按需启动的独立设置进程

设置界面使用同一可执行文件的私有子进程模式运行。主进程首次收到打开设置请求时启动
子进程；正常关闭先确认待提交设置已保存，再结束界面进程。下一次打开重新创建进程，
不保留隐藏的 WinUI 设置窗口。该模式是正常设置入口的实现，不需要用户开启调试工具。

## 进程和数据边界

- 主进程持有 SettingsController、WidgetEngine、组件设置服务、组件管理和备份后端。
  配置只有主进程负责写入，实时预览仍调用现有桌面应用逻辑。
- 子进程只创建 WinUI 运行时、设置窗口、页面和代理。它在主入口提前返回，不创建
  DesktopApp、单实例锁、桌面组件运行时或崩溃看护进程。
- 通过两条匿名管道传递有界值数据，没有共享 C++ 对象地址。仅白名单内的三个句柄
  可以继承；父子必须是同一可执行文件身份和协议版本。`--settings-ui` 是私有启动模式，
  不是给外部工具使用的 CLI，不改变 Lua API、清单版本或组件 capability。
- 子进程先安装通知处理器，再订阅主进程状态；重新打开时更新订阅，旧会话的异步
  组件通知失效。普通设置编辑检查会话代次和域版本，Dock 同时检查任务栏版本；
  组件编辑继续使用既有 guard 和 opaque value 规则。
- 正常关闭必须取得持久化确认；保存失败不返回成功关闭。连接中断不会自动重试
  结果未知的写操作。已经到达主进程的待保存状态由主进程保留并可在下次打开时重试；
  尚未发出的文本编辑无法在界面崩溃后恢复。
- 文件选择和确认交互保留在可观察的界面链路中。组件文件选择允许等待用户，断开时
  仍能结束等待。备份后端的完成队列留在主进程，界面退出不冒充任务已完成。
- 主进程持有子进程作业句柄，主进程退出或主动关闭作业会回收设置 UI。用户从设置
  打开的浏览器等外部应用可以独立存活。关闭连接会回收管道、通信线程和进程句柄；
  主进程保留一个轻量消息端点，用于完成已启动的后端工作。

WinUI 私有堆、窗口和进程持有的图形资源随子进程退出回收。DWM、驱动、字体等共享
缓存不属于子进程私有内存，不能承诺关闭后全系统显存立刻回到同一数值。
参见 Microsoft 的[进程终止](https://learn.microsoft.com/en-us/windows/win32/procthread/terminating-a-process)
与[作业对象](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)文档。

## 回归与限制

已运行的真实设置场景：

- 14 个页面连续巡检三轮；正常关闭后子进程消失，主进程 PID 不变。
- 临时关闭快捷导航并关闭设置；新子进程正确读取保存状态，随后恢复原值。
- 切换英语后，设置导航和页面标题更新，再恢复系统语言。通用与导航配置文件与测试前哈希一致。
- 设置搜索定位已有音乐组件，加载专属字段，封面背景开关 On → Off → On，返回状态一致。
- 备份列表正常加载；恢复确认框停留超过 30 秒后取消，未执行恢复。
- 强制结束设置 PID 44992 后，主进程继续运行，新设置 PID 43228 正常打开。

自动化回归覆盖：值协议边界、Unicode、超大/截断数据拒绝、秘密字段不出现在普通快照、
嵌套双向调用、大于管道缓冲的数据传输、卡住的写端超时回收、反复连接句柄回收、
真实子进程启动/退出、关闭作业强制回收、保存失败拒绝成功关闭、重试保存、旧域/代次/
任务栏版本拒绝覆盖、主进程不创建 XAML 宿主以及子入口早于桌面初始化的架构约束。
这些测试加入现有目标，未新增测试可执行文件。

当前实机证据没有覆盖破坏性的备份恢复/迁入，保存失败采用可控存储故障注入测试。
2026-09-06，在请求确认桌面实时预览、音乐组件设置、热键录制/使用及关闭重开保留后，
用户回复“可以了”。据此补齐本轮场景的用户实机验收；UIA 控件状态与用户反馈分别记录，
不扩展为所有组件或显示环境的验收。Steam/MSIX 部署下的完整交互尚未实机复测。

宿主性能探针目前只采集主进程，不会自动汇总设置子进程的 XAML 导航、布局或 GPU 数据。
评估设置时须同时记录主进程与设置 PID，子进程退出后应记录“已退出”，不能把采样缺失
伪装成仍存活进程的 0% GPU。详见[性能调试工具](performance_debugging.md)。
