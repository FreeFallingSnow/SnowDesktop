# Dock 恢复流程调整与验证（2026-09-23）

关联：[首轮排查记录](dock_restore_stall_investigation_20260923.md)。原始偶发故障尚未复现，本次候选针对已发现的输入队列耦合风险；不据此认定用户故障的根因或宣称实机问题已经关闭。

## 改动

- 移除 Dock 前台切换中的 `AttachThreadInput` 和立即强制重试。每次只向最终激活窗口提交一次普通前台请求，之后由观察器确认结果；未立即进入前台不再被当作必须合并输入队列的失败。
- 观察间隔为 100 ms。恢复等待从点击提交开始最多保留 5 秒；观察到退出最小化后，置前重试最多再保留 1 秒，且不能超过原来的总期限。重复观察不会续期。超时停止的是观察和置前重试，不会撤回已投递给 Windows 的显示命令。
- 观察项记录目标 PID/TID；句柄转交给其他进程或线程后，旧请求不再继续激活该目标。同进程同线程内的句柄复用没有新增完整生命周期令牌保证。
- 增加独立的 `DockActivation` 日志，记录显示请求前后、同步兼容回退前后、前台确认和观察结束时的目标/前台 PID/TID、最小化/可见/挂起状态、placement、显示命令及显示返回结果。没有记录窗口标题或内容。

上述均为宿主内部实现，没有修改公共组件 API、清单、capability 或版本要求。

## 风险与未覆盖边界

普通请求遵守 Windows 前台激活限制；系统拒绝切换时，候选不会再通过合并输入队列强行置前。该行为需在桌面 Dock、浮动 Dock、最后活动弹窗和不同完整性级别应用中实测。

为保持既有提升权限窗口兼容性，本轮保留异步显示被拒绝后的 `DefWindowProcW(SC_RESTORE)` / `SwitchToThisWindow` 回退，只补充前后诊断。最小化的默认窗口过程回退也未改造。这些同步调用仍可能等待外部线程，不能声称整条恢复流程已具有硬超时；观察期限不能打断同步 Win32 调用。若日志停留在对应 `before-*` 阶段，需继续用现场线程栈确认并单独改造该回退。

## 回归覆盖与负向对照

复用 `dock_and_window_rules`，替换原先要求“附加队列重试”的测试：

- 普通前台请求延迟完成时，当前调用返回待观察；后续已经进入前台时不重复请求。
- 恢复始终未完成、恢复很晚才完成、已经显示但不能置前时，观察状态均在固定期限结束。
- 目标进程或线程改变时，观察身份检查失败。
- 复用现有源代码负向边界，禁止 Dock 窗口跟踪实现再次调用 `AttachThreadInput`。这是架构约束，不作为运行时线程行为证明。

隔离探针直接提取本次测试中的观察状态断言，包含生产 `dock_window_rules.h`。当前头文件通过；隔离副本恢复旧的“窗口仍最小化时优先继续等待”分支后，测试在“过期恢复必须停止”的业务断言处失败，退出 1。两份探针均以 MSVC `/W4 /WX` 成功编译，未用编译失败充当回归证据。

另将当前测试所需的源文件复制到隔离目录，仅用 `7b01fe03` 的窗口跟踪源码替换该目录中的对应文件。当前测试程序检查此副本时，明确报告禁止的 `AttachThreadInput` 调用，退出 1；生产工作区未回滚。此对照证明负向架构约束能够捕获旧危险路径，不等于复现了 Win32 挂起。
