# 设置窗口、毛玻璃和隐藏页资源评估

本文保留同进程设置窗口的历史基线；后续实现与测量见[独立设置进程](settings_process.md)。

本轮只进行运行测量和源码审计，不修改宿主行为。被测日期为 2026-09-06，
Release 可执行文件 SHA-256 为
`89B26F03514F673BF7E06950A6AC7FC3789CF5BE80FE4B87D892D149917382C7`。
主进程 PID 19332，DWM PID 51876，24 个逻辑处理器。进程从已有桌面会话继续运行，
不是首次启动或首次使用设置的冷启动基线。

## 测量方法与证据边界

证据保存在 `artifacts/v1.0.5.0/performance/settings-resource-audit/`。
外部采样每秒记录进程私有提交、工作集、句柄、线程、CPU，以及按 PID 和引擎区分的
PDH GPU 使用率、专用和共享 GPU 内存。常规内存/GPU 对照期间宿主探针关闭。
单独的组件资源采集使用现有 `profile.bat` summary 模式，到期关闭，不混入关闭探针的样本。

设置页使用限定到 `SnowDesktop.WinUI3.SettingsWindow` 且核对 PID 的 UI Automation，
只导航、展开主题选项、临时切换材质及关闭独立设置窗口。没有枚举、截图或操作桌面宿主。
页面巡检顺序为：通用、主题与材质、组件与布局、桌面图标、图标美化、桌面、页面与网格、
分类与规则、Dock、Windows 任务栏、组件、备份、关于、组件开发工具，最后返回通用。
这覆盖 14 个不同路由；没有打开每个组件实例的专属设置，也没有展开所有延迟加载区块。

私有提交和工作集使用各稳定采样末尾 6 点的中位数；CPU 使用整段累计时间差，
按 24 个逻辑处理器归一化。GPU 使用丢弃第一点后的均值，保留引擎身份，不相加。
DWM 的 `% Processor Time` 原始计数同样除以 24 后才与主进程百分比比较。
GPU 内存计数不是精确的物理显存驻留，也不能与其他进程共享资源简单相加。

桌面、其他应用和 Codex 都仍在运行。DWM 是整个桌面的合成进程，这些结果是耦合场景的
对照趋势，不能把 DWM 全部资源归属给 SnowDesktop，更不能分摊给某个 Lua 实例。
没有采集堆分配栈、XAML 对象存活图或 ETW 的逐呈现 GPU 时间，因此不能据此证明具体
对象泄漏、驱动泄漏，或给出某个页面的精确资源账单。UIA 本身也可能改变框架缓存状态。

## 设置窗口关闭后的残留

| 场景 | 私有提交 MiB | 工作集 MiB | 句柄 |
|---|---:|---:|---:|
| 已运行会话，设置关闭 | 347.19 | 163.87 | 2423 |
| 仅打开通用 | 347.47 | 185.44 | 2461 |
| 首轮访问全部路由后返回通用 | 381.93 | 230.34 | 2494 |
| 第 1 轮关闭 | 374.58 | 218.53 | 2461 |
| 第 2 轮关闭 | 375.06 | 225.52 | 2474 |
| 第 3 轮关闭 | 387.44 | 239.08 | 2479 |
| 第三轮关闭后再等 45 秒 | 388.84 | 239.79 | 2479 |

前三轮后的私有提交残留约 **41.65 MiB**。工作集也未回到起点。已观察到残留，
但三轮及短暂等待不能区分框架/字体/图标缓存、分配器保留与未释放对象，不定义为已证实泄漏。

随后补充第 4～6 轮，关闭后私有提交分别为 400.29、411.19、410.00 MiB；最后再等 30 秒为 411.12 MiB。
这组中间已做材质对照，且用户在补充采样期间切换桌面页，工作负载不同；
不能把与 347.19 MiB 起点的全部差额认定为设置泄漏，也不能用末两轮接近就证明长期无增长。


已经确认的生命周期：

- `SettingsWindowHost::HideWindow` 刷新待提交值，结束设置会话，关闭页面后端并隐藏窗口；
  下一次 DispatcherQueue 回调调用 `ReleaseSessionView`。
- `SettingsShell::ReleaseSessionResources` 从可视树移除页面，逐个 Deactivate/Close，
  reset 各 presenter，清理搜索和焦点引用；它并非仅将页面设置为不可见。
- Shell、DesktopWindowXamlSource 和导航根作为进程级资源保留。现有代码明确记录过反复
  重建 Island/Shell 会带来 SVG 文件、映射和合成句柄残留，因此不应直接改成每次销毁整个 WinUI。
- 关闭后 2 秒，仅在工作集相对本次打开基线增长至少 64 MiB，且距上次缩减至少 30 秒时，
  才调用 `SetProcessWorkingSetSize(-1,-1)`。这不是释放私有提交或清除 GPU 资源。
  Microsoft 的 [EmptyWorkingSet 文档](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-emptyworkingset)
  说明该操作移出工作集页面；不能用工作集下降证明泄漏已解决。

首轮逐路由即时读数中，组件页约增加 12.6 MiB，备份约增加 5.0 MiB，Dock 与任务栏合计
约增加 7.8 MiB。这些是顺序访问时的进程增量，含异步完成、框架预热和其他模块活动，
仅用于安排排查顺序，不是页面独占内存。

## 毛玻璃对 DWM 的影响与关闭边界

使用相同颜色、透明度和 24 像素模糊半径的自定义主题，执行 on → off → on → off。
每次修改后关闭设置窗口，再采集 20 秒。进入自定义主题会联动快捷导航和组件/Dock 弹窗主题，
已在第一段前将它们恢复为原值，四段仅切换 `glassEnabled`。完成后恢复原深色毛玻璃主题；
`restoration.json` 记录外观和通用设置逐字段比较均无差异。

| 顺序 | 全局毛玻璃 | 主进程私有 MiB | 主进程 CPU % | DWM 私有 MiB | DWM CPU % | DWM 3D % | DWM 专用 GPU MiB |
|---|---|---:|---:|---:|---:|---:|---:|
| glass-on-a1 | 开 A1 | 389.27 | 0.280 | 665.50 | 1.190 | 1.502 | 1871.91 |
| glass-off-b1 | 关 B1 | 390.02 | 0.279 | 417.22 | 1.121 | 1.345 | 1663.89 |
| glass-on-a2 | 开 A2 | 389.86 | 0.275 | 417.27 | 1.196 | 1.434 | 1653.53 |
| glass-off-b2 | 关 B2 | 389.03 | 0.316 | 417.26 | 1.139 | 1.248 | 1651.01 |

引擎为 LUID `0x00000000_0x00016552`、`eng_0_3D`。两组关闭后 DWM 3D 均值
分别低约 **0.157 和 0.186 个百分点**，主进程 CPU 没有一致改善。
仅两组、未控制整个桌面的动态背景和其他应用，保留为趋势，不宣称确定因果或固定降幅。

第一次关闭后 DWM 私有内存从约 665.50 降到 417.22 MiB，但再次开启仍约 417.27 MiB；
GPU 内存也没有重复出现同样的回升/下降。因此不能声称关闭毛玻璃稳定释放约 248 MiB。
全局组件开关确实改变了持久化配置并经正常设置入口应用，但当前探针尚未直接统计所有
毛玻璃面板、工厂或 Mica 对象存活，不能用 PDH 差额证明每一个模糊资源均已销毁。


这是全局组件材质开关的对照，不是关闭 Windows 全局透明效果，也没有禁用任务栏 Hook。
任务栏、单实例外观覆盖、浮动窗口和菜单有独立的材质设置；全局关闭不意味着全进程再无模糊。

源码中的释放边界：

- 桌面组件重绘不再请求毛玻璃时，`app_widget_composition.cpp` 调用 `RemovePanel`，
  从 Composition 可视树移除该 SpriteVisual，并释放宿主持有的面板引用；完整场景收集还清理
  未出现的面板。窗口区域同步收缩为当前面板集合，零面板时是空区域。
- `DesktopBackdropCompositor` 的 `blurFactories` 按整数半径缓存，输入夹到 0～48，
  理论上最多 49 项。面板移除后没有立即清理工厂；工厂在 `Reset` 才清空。
  合成目标、根节点和共享 compositor/dispatcher 也可能继续存在。
- 设置背景走 `MicaBackdrop`，与组件 `CompositionBackdropBrush` 不同。
  当前隐藏设置窗口及 `ReleaseSessionView` 没有主动清除 Island 的 SystemBackdrop；
  `ApplyDeferredSystemBackdrop` 也没有窗口可见性条件。完整 Detach 才显式清除背景。
  这能证明对象的保留策略，不能直接证明隐藏时 DWM 仍持续绘制。
- Mica 取壁纸形成背景，不等同于实时模糊背后窗口；Microsoft 说明它为性能设计、
  仅取样壁纸一次。[Mica 文档](https://learn.microsoft.com/en-us/windows/apps/design/style/mica)
  因此应单独验证其隐藏释放收益，不能套用桌面实时毛玻璃的测量结果。

## 暂时不显示的页面

设置页切换会从 `PageCards` 可视树移除原页，并停用相关 presenter 和页面后端，
但在设置会话内缓存已经建立的控件，直到窗口关闭。页面与网格的 500 ms 定时器在
Deactivate 中停止。分类“已保存”提示的短时计时器会自行到期，Close 时撤销，
但 Deactivate 没有显式停止它；不能笼统地说隐藏设置页的全部计时器都为零。
没有证据表明全部隐藏设置页仍持续呈现。与此同时，`SettingsShell::ApplySnapshot`
仍会向已经创建的通用、外观、桌面、Dock、首页/关于 presenter 发送快照；
后台状态变化可能更新未显示控件，需与主动绘制区分。

桌面页的策略不同：`SetDesktopWidgetCompositionVisible(false)` 把 clip 收缩为零，
移除对应毛玻璃面板，但保留 `item.surface`、visual 和尺寸。真正的宿主隐藏会停止动画帧，
通知数据订阅可见性并清理本轮已有的背景/文字布局缓存；Lua 状态、原始视图树、运行时图片、
包图片和部分已上传位图仍可能保留。拓扑变化保活、打开辅助面板及允许隐藏运行的任务是例外，
不能用“不可见”推导所有后台工作必须为零。

用户回复“已切换”后，在设置已关闭的状态采集 12.014 秒；之前的对照为 10.003 秒。
两份 summary 报告的 droppedEvents、droppedGroups、droppedLinks、probeErrors 均为 0。

**隐藏停止绘制已得到实际证据；隐藏表面释放没有发生。** 10 个隐藏实例中，
`widget-144571000-32` 和 `widget-24148000-30` 仍分别收到 6、4 次失效通知，
但没有触发它们的视图绘制。留在可见状态的频谱实例仍正常绘制，不能当作隐藏页偷跑。

新页新增一个表面，故不能直接把全局表面总数增长当作泄漏。6.59 MiB 是本次隐藏实例
表面像素容量估算，不是可保证回收的显存；包图缓存为共享资源，不能全归属隐藏页，
也不能与驱动资源和 COM 对象内存相加形成完整账单。运行时图片令牌在本场景原本为零，
没有验证播放封面/切歌图片的隐藏释放。两次采样之间还有设置和材质操作，Lua 总量差额
不能只归因于切页。隐藏采集完成后已告知用户可以切回原页。


## 优化顺序

1. **先定位设置重复关闭后仍增长的私有提交。** 为各 presenter、后端、订阅、计时器、
   图片来源和 XAML/合成对象增加默认关闭的生命周期计数，配合堆/对象存活证据。
   先查组件、开发工具、备份和图标资源；对关闭后仍存活的引用逐项追踪。
   不降低工作集缩减阈值来代替真实释放，不直接销毁整个 WinUI 根。
2. **对隐藏桌面组件实施有预算的表面保留。** 候选方案是短暂隐藏保留、长期隐藏或超过
   字节预算后解除 visual 内容并释放表面，恢复时只重建该组件。保留 Lua 业务状态，
   防止提醒、下载和组件状态丢失；验证返回页面的首帧、动画、辅助面板和多显示器迁移。
3. **收紧零面板和窗口隐藏后的材质生命周期。** 零面板时清理无消费者的模糊工厂；
   设置隐藏时清除 Mica，重新显示时恢复，并防止排队回调在隐藏后重新开启。
   先测释放与重建成本，再决定是否延迟释放；不承诺能回收观察到的全部 DWM 内存。
4. **降低未显示设置页的更新和缓存量。** 不活跃页先存最新数据、激活时应用，
   图标库和包列表按需构造，较重 presenter 采用有限缓存。必须保留未提交编辑、
   颜色编辑器提交、异步任务和代际校验，避免为了节省内存丢失用户操作。
5. **最后再调整毛玻璃画质。** 在动画背景、拖动和多显示器场景重测模糊面积、半径、
   重复面板和合成提交。当前短采样不足以支持全局降画质或宣称某个固定 GPU 降幅。

以上是待实现、待验证的方案。本轮没有改动 C++、Lua、公共 API 或产品设置流程，
没有为纯评估重新构建或重复完整测试；验证来自实际场景、报告完整性、配置恢复检查和源码审计。
