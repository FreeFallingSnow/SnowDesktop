# 事件刷新合并验证（2026-09-06）

本轮完成同一宿主事件/计时器事务内的刷新去重。Lua 主动
`widget.invalidate()` 和事件成功后的自动刷新可以继续同时使用；请求按实例与
surface 合并，脏矩形取并集，全量刷新优先。最外层事件恢复 Lua/绘制上下文后，
仍在当前输入消息或计时器分发内调用宿主绘制，不新增定时器或消息等待。

实现尝试：`143247c4`。对照版本：`39fd2d10`。两者均为本地
`release/v1.0.5.0` 的构建，未修改运行中的组件包、布局或播放控制。

## 真实耦合采集

当前桌面中的音乐控制、音频频谱、时钟、系统状态及其他组件共同运行。
每次采集约 10 秒；优化后重启应用并预热 15 秒再采集。CPU 百分比按本机
24 个逻辑处理器归一化；下表的关闭探针 CPU 是各次采集结束后的独立约 10 秒
进程累计 CPU 差分。未将短跨度线程 CPU 行相加来分摊成本。

用户确认第一次复采期间操作了桌面后，追加两轮保持现有桌面状态的测量。
下表使用优化前基线及这两轮追加测量；三个报告均没有记录到额外的 desktop
paint/background/overlays scope。此前含用户操作的复采不用于下表的 CPU 比较。

重测动画事件频率为 59.82 Hz、59.79 Hz，基线为 59.56 Hz；音乐控制绘制频率从
170.17 Hz 降到 110.65–110.78 Hz；全局提交从 222.24 Hz 降到
162.58–162.76 Hz，减少约 26.8%。这次下降来自刷新合并，没有通过降低动画事件
频率获取收益。两轮关闭探针的 CPU 观测相对基线下降约 16%–23%。GPU 引擎数值
是进程级平均占用，不是单组件 GPU 时间，各引擎百分比不能直接相加。

首次优化后采集为 600 次动画事件，每次仅绘制一次；之后含用户操作的复采记录了
5 次额外桌面背景绘制，其 565 次动画事件也各仅绘制一次。这两份原始报告保留作为
过程证据。Windows 调度、媒体内容及后台工作仍有变化，不能将 CPU 差值外推为所有
机器和场景的固定降幅，也没有把重启前后的内存差异当作内存优化结果。

父子事件和 `widget.draw.source` 的来源关联均用于核对：优化前每个动画事件的
两条刷新请求分别进入两个 draw；优化后两条请求指向同一个 draw。三个报告的
事件、分组、来源关联丢弃数及探针错误数均为 0；追加的两轮重测也均为 0。

## 构建和测试

- `scripts/test.bat name widget_runtime_scheduler`：1/1 通过。新增覆盖保护最终
  model 一次绘制、嵌套事务、实例/surface 隔离、脏区域并集、全量刷新、事件外同步
  反馈、重入及原生异常后的派发恢复。
- `scripts/build.bat --reload-shell`：标准 Release 构建通过，生成
  `.build/Release/SnowDesktop.exe`。仍报告既有 WinUI 生成代码 C4002 与
  `widget_engine.cpp` 中既有 snapshot 变量遮蔽 C4456 警告。
- `scripts/test.bat full`：115/115 通过，测试输出隔离检查通过。首次运行因提前
  恢复应用而在重新链接时触发 LNK1104 文件占用，尚未执行用例；关闭该构建的宿主
  进程后重跑成功。不是通过重试隐藏测试用例失败。
- `scripts/profile.bat status -TargetProcessId 27244`：采集结束返回 `idle`，
  应用保持运行，采集未常驻开启。

尚未完成桌面/面板视觉、点击、拖动及 Dock 跟手性实机验收。本次验证确认刷新次数
和当前耦合场景的性能观测，不代表所有视觉与交互场景已经验收。跨组件按帧合批、
音频逐订阅分发、静态背景缓存和设置窗口评估属于后续优化范围。
