# Dock 文件夹弹窗启动状态与动画快照（待实机验证）

## 问题与证据

- 用户反馈：启动阶段打开 Dock 文件夹弹窗显示“无法访问此文件夹”，恢复显示后动画仍疑似带着错误画面。
- 排查基线：`0486b308281826b843e891b7d8438c26cf68b228`；开发 EXE SHA-256 为
  `5a82f16ebcc58311746121ef3bdce864799da766e697eb93c7d12038926bd230`。
- 保存了最新两个 UTF-16LE 日志到本机忽略目录 `.codex-probes/dock-popup-loading-20260922/`。
  日志中存在 `Folder refresh async: folders=1 readMs=0` 和弹窗输入记录；旧日志没有弹窗读取状态或快照版本，不能仅凭这些记录证明动画缓存残留。
- 代码链路确认：`ResolveDockFolderTarget` 异步未返回时，映射目标保留路径但 `available=false`；
  `OpenDockFolderPopupAt` 将它存入弹窗状态。`RefreshDockFolderPopup` 又使用这个旧值阻止目录读取/结果应用，
  目标解析回调也不更新已打开的弹窗状态。因此首次未就绪会被误报为无法访问，并挡住后续成功结果。
- 内容绘制优先使用 `popupAnimationOverlay_` 或 `popupAnimationRenderCache_`。目录刷新更新条目和几何时没有使这两个快照失效；
  弹窗图标完成回调还在刷新 Dock 窗口而非承载内容的独立弹窗。以上是代码推导的缺口，原始桌面动画仍需实机验收。

## 本轮改动

- 弹窗读取不再以异步 Shell 目标分类的 `available` 为前提，直接经已有目录工作队列读取；请求合并和版本校验继续由该队列负责。
- 新增独立加载状态；读取完成后按实际结果更新可用性。失败结果也会送达弹窗，避免一直停在加载中。
  失败保留已有条目但禁用依赖可用性的操作；不存在的目录清空旧条目并标记不可访问；可访问的空目录显示空状态。
- `FolderSnapshot` 保存 Win32 错误码，以区分不存在的目录与空目录；这是宿主内部数据，不改变组件公共 API。
- 条目、几何和异步图标变化时废弃位图、合成快照及旧完成回调，按已过去的时间继续当前动画方向。
  已结束的关闭正常收尾，已结束的打开直接绘制新内容；不会为每个图标重复录制 GPU 快照。
- 开启/切换 Dock 弹窗时先清理旧快照；加载提示同步提供全部十种界面语言翻译。
- 增加 `Dock folder popup read` 日志，记录可用性、错误码、条目数和目标路径。

## 回归边界

- `slot_runtime_contract` 中的目录测试使用生产 `dock_folder_popup_read::Refresh`，仅替换队列与条目提交边界。
  覆盖启动时目标未就绪仍发起读取、成功结果提交、访问失败保留条目、重试恢复、其他目录迟到结果、缺失目录及空目录。
- `popup_animation_rules` 使用生产状态和 `RefreshContent`，仅替换 GPU/完成回调资源释放。
  覆盖打开中到达、关闭中到达、关闭结束后到达和打开结束后到达，核对快照释放、方向及时间进度。
- 隔离副本负向对照：恢复旧可用性门槛、不释放旧快照、内容变化重置时间线三种变体都编译成功且触发预期失败；候选通过。
  未用编译错误、超时或桌面自动化作为故障复现。
- 未执行桌面宿主视觉自动化；自动测试不证明实际 DComp 画面和交互观感。
