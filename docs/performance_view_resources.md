两轮解析、布局和原生视图绘制分别各发生 1814、1786 次；动画 frame 为 1777、
1739 次。第一轮组件表面作用域完成 1813 次，与视图阶段差一次来自采集边界，
不将跨边界未结束作用域补算为完整调用。

这些是 self 经过时间，包含等待及被抢占时间，不等于精确 CPU 时间，也不是 GPU
执行时间。5 秒逐作用域 CPU 追踪出现大量 0 和 15.625 ms 量化值，包括解析累计
58.175 ms wall 而 self CPU 为 0；不能据此认为解析不消耗 CPU。
参数构造每轮约 64～68 ms，明显小于解析和绘制，不能再把原先 widget/context
的全部 self 时间解释为上下文构造成本。

第一、二轮 summary 分别包含 7、17 次 desktop paint，5 秒 trace 无 desktop
作用域。进程 CPU 分别为 0.927%、1.211%、trace 1.000%；场景和采集模式不同，
本记录不据此宣称此次诊断改动降低了进程 CPU。

音乐 Lua 堆第一轮为 191072～370447 字节，随 GC 波动。旧报告中全部 Lua 堆
峰值之和约 2.2～2.5 MiB，没有与此前进程私有提交约 31 MiB 差额相当的变化。
此次约 89 秒的进程检查点从 215.629 MiB 到 221.715 MiB；其中 5 秒 trace
前后从 216.152 MiB 到 218.641 MiB。此数据不构成固定封面序列的长期内存
对照，不能确定差额来自驱动、未覆盖原生对象、分配器保留或其他来源，也不能
宣称无泄漏。最后一轮保留了第二张运行时封面和两项额外文字格式，说明工作负载
并非完全固定；新增封面像素数据仅约 71.2 KiB，无法单独解释此前约 31 MiB 差额。
各轮内部图片资源采样范围相同，只能说明其在各自窗口内保持稳定。

随后保持内部探针关闭，外部每 10 秒读取一次进程计数器，共 7 点、60.16 秒。
私有提交为 230.137 → 231.152 MiB，范围 229.094～231.184 MiB，非单调变化；
该窗口进程 CPU 为 1.014%。开始和结束状态均为 idle。此一分钟观测也不能
代替长时间、固定内容的内存回归验证。

资源采样两轮分别执行 31 次，累计 wall 为 1.148、1.316 ms，即每次约
0.037～0.042 ms。trace + ScopeCpu 的 6 次累计 0.243 ms。这只衡量新增资源
遍历，不是整个探针开销；阶段埋点、采集器和报告导出成本仍包含在进程指标中。
