# 音频订阅限频与动画合帧实测

验证对象：`a98499ca`。2026-09-06，同机同布局的 Release 耦合场景，音乐控制
与频谱、时钟等组件共同运行。采集配置均为 `trace`，不启用逐作用域 CPU。
音乐实例 `widget-133060937-33` 对应 Aurora 包
`20437e72-af2b-4e19-9f6b-30efb9bb5f6e`；未修改该 Lua 包。

## 原因与改动

音乐请求 30 Hz 音频分析，但原先共享源每次变化都使所有订阅者失效，实测为
50 次/秒，再叠加约 60 次/秒唱片动画和少量媒体变化，达到约 111 次绘制/秒。

现在音频重绘通知按每个订阅自己的间隔限频，并排入同实例下一次宿主帧：
已有动画帧复用同一截止时间；没有动画时使用一次数据刷新；宿主无法调度时
保留同步失效回退。取消命名动画不取消数据刷新，隐藏会清理排队状态。
交互触发的同步失效入口和主动读取最新共享快照的行为保持原样。

30 Hz 被换算为至少 34 ms 的投递间隔；当前共享源约每 20 ms 发布，因此音乐
重绘通知实际约为 25 Hz。这是上限请求，不是固定帧率保证。组件仍在约 60 Hz
唱片动画中读取最新共享样本；减少动态效果也不会由宿主压掉数据刷新。

## 结果

每个版本两次 10 秒采集。四次均无 desktop 埋点绘制事件，所有丢弃和 probeErrors
均为 0。音频源与动画同步来源关联显示，每次动画只触发一次音乐绘制。

| 指标 | 合帧前两轮 | 合帧后两轮 |
|---|---|---|
| 音乐绘制 / 10 秒 | 1109、1108 | 617、617 |
| 音乐 frame / 10 秒 | 598、598 | 607、607 |
| 独立频谱绘制 / 10 秒 | 501、500 | 496、493 |
| 整体合成提交 / 10 秒 | 1630、1628 | 1132、1129 |
| 开探针进程 CPU | 1.677%、1.659% | 1.061%、1.171% |
| 关闭探针进程 CPU | 1.652%、1.546% | 1.151%、1.066% |
| GPU 3D 引擎平均 | 2.186%、2.151% | 1.439%、1.447% |
| GPU Copy 引擎平均 | 0.531%、0.542% | 0.314%、0.323% |
| 关闭探针时私有提交 MiB | 209.36、210.61 | 207.83、207.80 |

音乐绘制减少约 44.3%，整体合成提交减少约 30.6%。合帧后音乐每轮接受 250 次
音频刷新，其中 247/246 次与动画来源对应到同一绘制，分别约 98.8%/98.4%。
后台没有新增永久帧循环，采集结束状态为 idle。

CPU 为逻辑处理器归一化的进程值；关闭探针对照的基线窗口为 5 秒、新版为 10 秒。
GPU 是同一适配器下该进程的单个 3D/Copy 引擎计数器均值，不能相加，也不能归属
为音乐组件独占占用。短测仍有负载波动；内存只作观测，不宣称消除泄漏或固定降幅。

## 剩余优先级

1. 背景模糊缓存已在后续尝试中实现并完成自动化及播放性能验证，见
   [装饰背景模糊缓存验证记录](performance_background_cache.md)。Lua 回调仍逐帧执行，
   仅复用确认不变的模糊结果；后续切歌封面更新等三项用户实机验收已记录。
2. 将唱片旋转与整棵 Lua view 重建进一步分离。需要独立视觉/合成能力与兼容验证，
   不能仅减少回调次数后声称已保留动画效果。
3. 继续按场景测量暂停、隐藏、设置窗口打开和关闭、组件增减；不从单次短测推断
   所有布局或机器的收益。
