# 映射目录与 Dock 目录变化刷新验证

本轮候选基于 `8296b4bec200e48521f3af5e4ec392a37b73bd5c`，位于 `release/v1.0.7.0`。
仅调整宿主内部的通知和刷新流程，不新增或修改 Lua 组件 API、清单、权限和 capability。

## 行为与范围

- 映射组件（包括文件组子组件、Dock 中的映射组件）订阅其源目录直接子项变化。
- Dock 普通目录在弹窗打开时订阅，关闭或切换弹窗时释放不再被组件引用的订阅。
- 大小写、尾部分隔符和同一路径的重复引用合并；Shell 解析得到的长路径用于匹配通知，
  原路径用于选择组件。长短路径别名共用注册。
- 目录消息复用 50ms 合并、串行后台读取、版本检查，以及拖动、菜单、重命名和文件操作期间的
  延后提交逻辑。新消息使旧快照失效，但保留本批所有待刷新目录。完整刷新请求优先。
- 目录专用快照只枚举受影响目录，不枚举桌面和其他映射目录，不重建整个桌面容器。
  更新对应映射列表、文件组缓存和当前 Dock 弹窗，保留现有项选择、图标及排序规则。
- 枚举失败保留原列表；没有定时目录全扫描。注册失败在下一次模型重建或弹窗同步时重试。
  根目录暂时不可用、网络盘恢复和持续高频写入尚待实机验证，不声称所有环境下即时刷新。

## 自动证据及边界

复用 `slot_runtime_contract`（含 `integration` 标签），新增用例位于
[`shell_folder_refresh_cases.h`](../tests/shell_folder_refresh_cases.h)。

- 真实入口：生产的 `FolderNotifications::Sync/Affected`、`FolderRefreshScope`、
  `SelectFolders` 和 `ReadSources`；沿用已有 `Revision` 和状态保留回归。
- 隔离 Windows 接收窗口和临时目录中，通过普通文件写入触发文件系统通知，不手工发布新增文件
  的 Shell 通知；分别检查映射目录与 Dock 普通目录能收到并路由变化。窗口不属于桌面宿主。
- 检查目录/子项事件、跨目录重命名两端、排除无关和更深层目录、重复注册、弹窗关闭、
  映射移除/切换、注销与重新注册。
- 刷新范围测试替换文件系统读取边界，直接计数桌面、目录和 Dock 检查调用；确认目录通知不触发
  无关读取、同路径只读取一次、完整刷新不被目录请求缩小。此项不等同于整个 DesktopApp 实机运行。
- 初次真实通知测试失败。隔离诊断证明消息已到达，但 `%TEMP%` 使用的 8.3 短路径与 Shell 返回的
  长路径不同；增加注册时的路径别名映射后通过。另曾调整接收窗口为 WndProc 记录消息，单独调整
  接收方式没有消除失败。没有把超时或沙箱阻断当作产品缺陷复现成功。
- 隔离副本的两项负向对照：清掉先前待刷新目录、强制退回完整读取。未变异基线退出 0，两个
  变异分别由相关行为断言失败并退出 1。未修改工作区生产代码来制造失败。

本地输入清单、源码差异及日志保存在 `.codex-probes/folder-notifications/`。
配置为 Release，MSVC 14.50.35717，Windows SDK 10.0.26100.0。

## 待实机验收

使用最终构建，选取独立测试目录，在资源管理器或其他程序中新建、复制、重命名和删除文件：

1. 桌面映射组件、文件组中的映射子组件、Dock 映射组件分别保持显示，观察列表和数量更新。
2. Dock 普通目录弹窗保持打开时修改目录；关闭后再次修改，再打开应读取最新内容。
3. 两个组件和一个 Dock 弹窗引用同一路径，修改后均更新；移除一个引用不影响其他引用。
4. 批量复制期间检查响应；拖动、框选、重命名和菜单交互结束后应补上变化，并保留排序和选择。
5. 删除映射组件、切换 Dock 目录、恢复桌面宿主后，确认旧目录不再影响无关列表，新目录仍刷新。

尚未运行桌面宿主自动化，也未以构建或规则测试替代这些交互验收。
