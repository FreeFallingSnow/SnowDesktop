# 装饰背景模糊缓存验证记录

验证对象：`d2a66be3`、`cc28b8e3`。2026-09-06，Windows 11，Release，
NVIDIA GeForce RTX 5070 Ti Laptop GPU。音乐控制实例 `widget-133060937-33`
与频谱、时钟等组件共同运行。此记录只验收自动化像素对照、缓存边界和运行时性能，
不代替用户对桌面视觉、切歌及播放控制的实机验收。

## 原因与实现

音频合帧后，唱片动画仍使整个组件约每秒绘制 60 次。此前每次绘制都会录制
封面背景和渐变，再创建高斯模糊效果，即使背景内容没有变化。

现在宿主保存完成模糊后的位图。Lua 背景回调仍按原来的时机执行，宿主逐条比较
所支持绘图命令的完整签名；图片、颜色、渐变参数、尺寸、DPI 或模糊半径变化时
重新生成。签名保留输入图片引用，避免资源地址复用命中旧画面。仅宿主已知不可变
图片、实色/线性渐变矩形等可分析命令参与缓存；未知命令、效果、可变图片、
缩放或非整数像素变换回退到原有路径。没有修改 Lua 包或公共组件 API。

缓存最多 32 项，单项估算 8 MiB，总保留资源估算 32 MiB。估算包含输出位图、
被缓存引用的输入图片及签名，不代表驱动、DWM 或生成过程的全部显存。
隐藏、卸载、资源清理、设备变化时相应清理；超限按最近使用顺序淘汰。

`widget.background.cache` 的 `hit`、`miss`、`bypass` 计数按组件实例记录，
`retained_bytes_estimate` 是整个引擎缓存的估算字节数。探针默认关闭，
这些观测不产生常驻采集任务。

## 播放场景结果

比较音频合帧版与背景缓存版，配置均为 `trace`，不启用逐作用域 CPU。
每轮采集 10 秒，随后关闭探针读取 10 秒进程累计 CPU。

| 指标 | 音频合帧版两轮 | 背景缓存版稳定播放两轮 |
|---|---|---|
| 音乐绘制 / 10 秒 | 617、617 | 611、609 |
| 音乐 frame / 10 秒 | 607、607 | 599、599 |
| 独立频谱绘制 / 10 秒 | 496、493 | 480、479 |
| 整体合成提交 / 10 秒 | 1132、1129 | 1109、1108 |
| 开探针进程 CPU | 1.061%、1.171% | 1.014%、1.054% |
| 关闭探针进程 CPU | 1.151%、1.066% | 1.021%、1.009% |
| GPU 3D 引擎平均 | 1.439%、1.447% | 0.987%、1.034% |
| GPU Copy 引擎平均 | 0.314%、0.323% | 0.177%、0.181% |
| 缓存命中 / 未命中 / 回退 | 尚未实现 | 611/0/0、609/0/0 |
| 缓存保留资源估算字节 | 尚未实现 | 743436、743436 |
| 关闭探针时私有提交 MiB | 207.83、207.80 | 238.63、238.76 |

暖缓存两轮命中率均为 100%，约保留 726 KiB。相对音频合帧版，3D 引擎短测
均值降低约 30%，Copy 约 44%；关闭探针 CPU 均值降低约 8.5%，幅度较小。
这些是该机器进程在耦合运行中的观测，不是音乐组件独占 GPU，也不保证其他
机器、曲目、布局或 GPU 频率下具有固定降幅。GPU 引擎值不能相加。

稳定播放第一轮仍记录 2 次 desktop paint、3 次 overlays；第二轮没有 desktop
作用域事件，作为无桌面刷新干扰的主要对照。音乐 frame 和频谱绘制频率也有少量
差异，未控制 GPU 时钟，且两个版本并非同一进程内随机交替 A/B。此前用户已说明
额外桌面刷新来自手动操作，此记录不据此推断自动刷新缺陷。

私有提交比上一进程高约 31 MiB，明显大于本缓存的资源估算。本次跨进程短测
不能确定差额来源，不能宣称内存优化或无泄漏；仍需固定曲目/封面序列的长时对照。
缓存上限只约束本缓存保留的估算资源，不约束其他图片缓存或整个进程。

背景回调和命令录制没有跳过，背景作用域 wall time 从每轮约 127～130 ms 变为
134～142 ms；此作用域不是 GPU 计时。不能用缓存命中声称 Lua 回调 CPU 已消除。

## 排除的窗口

- `background-cache-after-1/2`：每轮音乐绘制 102 次，frame 为 0，频谱绘制 92 次。
  即使进程占用较低，也因负载不一致而不用于播放性能对比。
- 用户确认“已在播放，可以复测”后的 `background-cache-playing-1/2`：音乐
  frame 为 577/579 次，缓存全部命中，但有 6/11 次 desktop paint 和 8/57 次
  overlays，故不作为稳定 CPU 对照。
- 稳定窗口为 `background-cache-steady-1/2`。所有新采集的 droppedEvents、
  droppedGroups、droppedLinks、probeErrors 均为 0，最后状态为 idle。

## 验证与证据

- `scripts/test.bat name component_preview`：1/1 通过。复用既有集成测试目标，
  以 WARP 实际渲染缓存和直接模糊，对比 96/144/192 DPI、DIP/像素单位、圆角
  裁剪和透明度，8 位通道误差最多 1；独立验证颜色、图片、尺寸、半径变化，
  未知绘图回退、条目/字节上限、清理和设备切换。
- 首轮定向编译出现新增 C4458，`cc28b8e3` 调整参数名后定向构建不再出现。
- `scripts/build.bat --reload-shell`：标准 Release 通过，生成
  `.build/Release/SnowDesktop.exe`。本次增量构建仍报告既有 `snapshot` C4456。
- `scripts/test.bat full`：115/115 通过；完整测试完成后才恢复实际宿主。
- 实际性能采集使用现有控制窗口按 PID 调用，没有捕获或操作桌面宿主窗口。
  用户对唱片、背景外观、切歌、播放/暂停的实机反馈仍待完成。

## 后续优先级

1. 先细分视图构造、布局、原生绘制和状态保存的 CPU，再评估唱片旋转与整棵 Lua
   view 重建分离。现有 `widget/context` 包围执行上下文整个生命周期，其 self wall
   不是上下文构造耗时，不能据名称把全部时间归因于创建 Lua 上下文。
2. 用固定封面切换序列做内存长时对照，区分解码图片、背景缓存和其他资源。
3. 补充暂停、隐藏、设置窗口开关及组件数量变化的场景；视觉和桌面交互按仓库
   规则由用户实机验收。独立合成若涉及公共 API，须另行说明兼容与降级路径。
