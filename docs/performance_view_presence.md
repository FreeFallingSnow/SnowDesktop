# 视图缺省字段查询优化验证

验证对象：`ad115159`、`66365538`。2026-09-06，Release 实际宿主 PID 19416。
对照版本为 `327ac3c7` 的分段诊断构建，见
[视图分段与图片资源诊断验证](performance_view_resources.md)。

## 改动与兼容边界

原生解析器为每个节点检查大量可选属性；音乐组件每秒重建约 60 次视图，重复查询
没有使用的字段也有成本。现在每次解析先扫描节点原始字段，构造两个 64 位的
缺省筛选掩码。确认不存在的属性跳过 Lua 查询；可能存在的属性仍执行原查询。
哈希冲突只增加查询，不会跳过已有字段或改变属性值。

筛选对象只在本次原生解析中存在，不缓存 Lua 表或属性值，不增加持续资源缓存。
带元表、非字符串键、超过 64 个字段或字段名超过 64 字节时，回退原查询流程；
这些阈值限制筛选成本，不是新增的组件字段上限。原有 nil/false 区分、非法字段
拒绝、类型检查和错误处理仍保留。公共 Lua API、schema、capability 及组件包未变。

## 固定输入基准

独立诊断程序使用同一份 Lua 表，先验证解析与布局合法，再反复解析并销毁原生树。
旧、新解析器各运行三组，交替执行；每组丢弃一轮预热，保留七轮，每种输入每个
版本共 21 个样本。下表为每次解析加原生树销毁的中位时间，单位微秒。

| 输入 | 原查询 | 字段筛选 | 减少 |
|---|---:|---:|---:|
| 简单 box 节点，每轮 10000 次 | 4.219 | 3.229 | 23.5% |
| 播放器式视图、24 个频谱条及按钮，每轮 1000 次 | 187.507 | 151.619 | 19.1% |
| 64 个字段较多的文字节点，每轮 500 次 | 677.242 | 538.122 | 20.5% |

此区间不含 Lua view 回调、布局和绘制，不是整帧或应用 CPU 的降幅。临时基准未
注册为新的测试目标，也未把时间阈值加入 CTest。初始诊断程序的 CRT 配置和非法
非聚焦节点 tabIndex 已修正后才采集以上有效对照，早期无效输出未纳入统计。

## 持续播放实测

音乐实例 `widget-133060937-33` 与频谱、时钟等其他组件共同运行。两轮各 30 秒
summary，中间插入一次约 5 秒 trace + ScopeCpu，顺序与前一构建的诊断相同。
采集前后读取系统媒体状态均为 Playing，没有修改播放控制或组件包。

| 窗口 | 原解析次数 | 新解析次数 | 原每次 self wall ms | 新每次 self wall ms | 减少 |
|---|---:|---:|---:|---:|---:|
| summary-1 | 1814 | 1830 | 0.18594 | 0.15798 | 15.0% |
| trace + ScopeCpu | 308 | 308 | 0.18888 | 0.15930 | 15.7% |
| summary-2 | 1786 | 1840 | 0.19760 | 0.16640 | 15.8% |

新 summary 两轮音乐 frame 为 1797、1810 次，约 59.88、60.32 Hz，未通过降低
动画帧率取得解析收益。第一轮记录 3 次 desktop paint、5 次 overlays；第二轮
和 trace 无 desktop 作用域。旧 summary 两轮分别有 7、17 次 desktop paint，
旧第二轮还增加过一张封面，故这些实时结果是方向一致的支持证据，不能代替固定
输入对照。用户此前明确说明额外桌面刷新来自操作，不据此判断自动刷新缺陷。

新 summary 两轮进程 CPU 为 0.974%、1.100%，采集关闭后的两个约 10 秒窗口为
0.955%、1.008%。前一构建为 0.927%、1.211%（summary），存在波动重叠，本轮
不声称整个应用的固定 CPU 降幅。逐作用域线程 CPU 仍有计时量化，排行采用 self
经过时间；解析优化本身没有减少绘制次数，不宣称新增 GPU 收益。

三次新采集音乐封面均为 1 张/72900 字节，合成表面估算为 690060 字节，背景
缓存估算为 743436 字节；共享包解码图片为 2 张/12583536 字节，文字格式缓存
47 项。音乐 Lua 堆随 GC 波动。约 89 秒的进程检查点私有提交为 212.727 至
217.734 MiB，中间有下降；这不是长时间内存验证，也不能解释此前跨进程约
31 MiB 的差额。新筛选器无持续分配，不把这些进程差异归因为内存优化。

资源统计每轮执行 31 次，累计 wall 为 1.100、1.065 ms，约 0.034～0.035 ms/次。
这只衡量资源遍历，不代表整个探针开销。

## 当前优化优先级

已完成探针轻量模式、重复失效合并、音频与动画合帧、静态背景模糊复用及本次
缺省字段筛选，并分别保留测量记录。默认关闭、命令行限时采集、逐 Lua 实例及
共享成本归属均可用于后续耦合场景调试。

后续候选按证据排序：先评估减少唱片旋转引起的整棵视图重建和原生绘制；再用
固定封面序列做内存长时对照。暂停、隐藏、设置界面和组件数量变化需要分别建立
场景基线，当前播放数据不代表这些场景的性能结论。设置同步方法埋点也不能覆盖
完整 XAML 布局与 GPU 执行时间。独立合成若需新公共 API，应先评估兼容与降级，
不能从本次解析收益推导其具体收益。

后续已完成[文字布局复用验证](performance_text_layout_cache.md)，减少了当前音乐
视图的原生绘制经过时间；整树重建频率仍未改变，总 CPU 收益尚未证实。
