# Dock 图标延迟及文件夹打开动画调整

## 原始场景与证据

- 用户截图中的三个运行应用及右侧文件夹显示三个点，随后确认“等一会儿后自动恢复了”。这是延迟加载反馈，不作为永久取图失败处理。
- 基线 `a0e6f2b0`，开发宿主二进制 SHA-256 为 `79a3b6b49e02ed1383ad078ade0b9812e4e8dc037ba42af043c5410476cf7af9`。
- 2026-09-22 23:56:31 保存日志；该次启动为 `60464-213443906`，首帧 1172 ms，桌面交接 1359 ms。非侵入只读调试时三个应用为 FlClash、QQ、SnowDesktop 设置，均已持有图标位图，Shell 视觉队列为空。旧 Dock 路径没有独立排队/读取耗时，不能据此归因到某次具体 Shell API 阻塞。
- 代码确认：运行应用取图先经过 Shell 命名解析和系统图标查询，映射文件夹入口先查询系统索引，再另排位图提取。它们没有复用桌面第一阶段直接读取本地资源的路径，并与其他 Shell 视觉任务共用队列。
- 用户进一步反馈文件类 Dock 弹窗“打开时跳一下、闪一下或突然展开”。后续日志 `51620-214048406` 中，工作区、下载、快捷访问先显示 305×301 的空列表窗口，再于约 6–13 ms 后返回 13、6、9 个条目。与目录结果在打开动画中到达相符，不把日志当作实际画面验证。
- 代码还存在两处时序缺口：初次目录刷新在动画初始化前立即显示窗口；内容更新撤掉合成快照时，没有先提交新内容接替旧画面。已知条目数也没有用于加载阶段布局，导致空列表尺寸切到有内容尺寸。

## 调整

- Dock 图标使用独立的本地资源与 Shell 工作队列，各预留两个工作线程。运行中的普通 Win32 应用及映射文件夹可先显示本地资源，Shell 结果随后补充；有应用身份标识的打包应用仍由 Shell 选择图标，避免误用宿主 EXE。
- 两个阶段完成前合并同一请求；取消、退出后不提交迟到结果。增加本地/Shell 两阶段的排队和读取耗时日志。
- 映射文件夹缓存位图，移除系统索引到位图的二次排队。迟到的本地图标不能覆盖同轮 Shell 结果；刷新票据、失败五秒重试、设备/样式变更失效均保留。
- 首次打开只准备目录状态和几何，初始化动画后才显示窗口。加载期间以已保存的条目数预留布局；实际绘制和命中测试仍只访问真实条目。
- 内容变化时推进原时间线，先准备实时绘制内容，再撤掉合成快照与完成回调；过期位图不会参与交接，已经关闭的弹窗不重新显示。
- 全部为宿主内部接口，不涉及组件公共 API、版本或数据格式迁移。

## 测试范围与限制

- `slot_runtime_contract` 使用生产 Dock 调度器，仅以受控事件替代阻塞的 Shell 提供器。覆盖 Shell 全占用时后续本地图标仍完成、重复入队合并、取消和退出。
- `dock_and_window_rules` 覆盖本地/Shell 交错完成、过期票据、设备缓存清理、失败后迟到本地结果仍保留重试，以及工作区 13 个条目的加载布局。
- `popup_animation_rules` 使用生产时间线和交接函数，替换 GPU 准备/释放边界，验证替代画面先于旧快照退休、进度和关闭方向保留。它不证明 DComp 实际画面无闪烁。
- 本轮需要标准 Release 构建、上述定向回归与完整自动测试。原始证据保存在本机忽略目录 `.codex-probes/dock-missing-icons-20260922/`，不提交用户日志。
- 待用户实机验收：启动时应用/映射文件夹入口的首图速度；工作区、下载、快捷访问反复打开与切换时的动画；图标晚到、快速关闭再打开、扇形/网格/列表模式。
- 尚无目录条目数记录的首次访问仍会在真实结果返回时调整窗口大小；不为避免重排而阻塞界面等待磁盘。第三方 Shell 提供器的执行时间没有硬上限，本地通道隔离不等于所有来源都能即时返回。
