# 桌面点击闪动：候选改动与日志说明

## 证据与边界

用户提供的录屏中，3.806 秒和 3.874 秒各有一帧桌面图标、集合内容消失，壁纸和任务栏仍可见。用户反馈插电时也能发生，不能把电池供电当作必要条件。此前日志与录屏不是同一次操作，不能据其中的 `WM_SHOWWINDOW` 判断这两帧发生了窗口隐藏。

隔离桌面的机制实验确认：将渲染子窗口作为菜单 owner 时，Windows 将其顶层父窗口作为原生 owner；左键取消菜单已把焦点移到独立输入代理，菜单退出仍会激活父窗口并把焦点交回渲染子窗口。使用独立输入代理作为 owner 后，该次父窗口激活消失。

实验没有使用真实 Explorer、桌面合成画面或用户显卡环境，不能代替闪动的实机验收。本候选在原场景验证前按 `try` 交付。

## 候选范围

- 桌面渲染窗口对 `WM_MOUSEACTIVATE` 返回 `MA_NOACTIVATE`，保留点击消息，由交互处理器显式选择输入窗口。
- 普通桌面和浮动 Dock 会话的现代菜单归还焦点给各自输入代理；显式指定的其他 owner 保持原行为。浮动菜单的层级 owner 和层级下限继续单独处理。
- 菜单打开前使用输入代理；输入代理已经持有前台焦点时跳过重复请求。代理不存在时不回退激活 Explorer 下的渲染子窗口。
- 保留菜单退出后的绘制提交，避免影响取消菜单、键盘选择及 Shell 命令执行。

## 日志

日志沿用数据目录中的 `SnowDesktop.log`，轮转文件为 `SnowDesktop.log.1`，无需开启额外开关。新增内容不记录键盘文字或文件名。

`DesktopInteraction` 包含以下字段：

| 字段 / 事件 | 用途 |
| --- | --- |
| `id`、`seq`、`tick` | 关联交互过程，结合每行的实际时间戳定位录屏时刻 |
| `powerKnown`、`ac`、`battery`、`saver`、`frameLimit` | 区分插电、电池、省电及实际帧率上限；`ac=0` 为电池、`1` 为插电、`255` 为未知 |
| `message-before/after`、`msg`、`wp`、`lp` | 消息处理前后状态；`0x18` 为显隐，`wp=0/1` 分别表示隐藏/显示，`lp` 为原因 |
| `subject`、`render`、`parent`、`input` | 区分收到消息的窗口、渲染窗口、桌面父窗口与输入代理 |
| `foreground`、`active`、`focus`、`foregroundFocusKnown`、`foregroundFocus` | 同时记录局部焦点和真实前台输入队列焦点，不能只凭局部 `focus` 判断输入已转交 |
| `renderVisible`、`parentVisible`、`prev`、`rect`、`insertAfter`、`posFlags`、`xywh` | 检查显隐、层级和尺寸变化；可见标志不等于像素已经呈现 |
| `surface`、`commitPending`、`paintActive`、`recovery` | 检查合成表面重建、待提交帧和设备恢复 |
| `paint-enter`、`paint-queued`、`composition-commit` | 区分开始绘制、绘制完成待提交和提交结果；`hr` 记录 HRESULT，成功提交不等于屏幕已呈现 |

`ModernMenuZOrder` 另外记录 `focusOwner`、`focusOwnerRoot`、`active`、`focus`，以及菜单销毁、焦点恢复前后的检查点。与 `DesktopInteraction` 按时间对照，可以判断是否再次经过桌面父窗口。

窗口/焦点采样只在交互后的短时间内启用，并设数量上限；绘制/提交最多采样 12 条，避免持续逐帧同步写日志。生命周期和电源事件保留独立记录。它是有界诊断，不是完整帧追踪。

## 回归与实机验收

`modern_menu_interaction` 使用不切换到前台的私有测试桌面，经过真实菜单创建、取消、命令选择和销毁。新增检查覆盖桌面/浮动输入代理、外部点击取消、键盘选择、原生 owner 和父窗口激活。负向对照在隔离副本中恢复普通桌面使用渲染子窗口的行为，必须在父窗口归属/激活检查失败；不能用编译失败或超时代替该信号。

用户实机验收仍需覆盖：

1. 电池与插电状态下，左右键点击空白桌面；右键打开菜单，再左键空白区域取消。
2. 桌面图标选择、框选、双击、重命名及常用键盘快捷键。
3. 集合和 Dock 菜单的打开、取消、键盘选择、命令执行，以及浮动菜单的层级。
4. 点击外部应用关闭菜单，确认前台切换符合预期。

若仍闪动，记录操作发生的准确时间，并保留当时的 `SnowDesktop.log` 和存在时的 `SnowDesktop.log.1`，再与原始录屏对齐分析。
